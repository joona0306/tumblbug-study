# 상용 서비스 클론으로 배우는 제품 개발 (완전 초심자용 교재)

## 이 교재는
UI/UX, 프로덕트, 개발, 컴퓨터공학을 전혀 모르는 사람이 처음부터 끝까지 따라 하며
**실제로 배포되고, 실제 사람이 쓰는 서비스**를 만들고 → 운영하고 → 개선하는 전 과정을
배우는 교재입니다. 최종 목표는 **텀블벅 수준의 크라우드펀딩 서비스 MVP**입니다.

한 번에 텀블벅을 만드는 대신, 필요한 개념을 단계별로 나눠 프로젝트를 순서대로
완주하면서 실력을 쌓습니다. 단계마다 새 개념은 딱 하나씩만 추가됩니다.
전체 커리큘럼은 [`ROADMAP.md`](./ROADMAP.md) 참고.

| 단계 | 프로젝트 | 기간 | 핵심 학습 목표 |
|---|---|---|---|
| 0 | 기초 | 2주 | 웹 동작 원리, 터미널, HTML/CSS/JS, Git — 자기소개 페이지 첫 배포 |
| 1 | Linktree 클론 | 1개월 | 전체 사이클(기획→배포→운영) 1회 완주, 로그인 원리 |
| 2 | Buy Me a Coffee 클론 | 1개월 | 결제 연동 (테스트 모드) |
| 3 | 당근마켓 미니 클론 | 1개월 | 1:N 데이터 관계, 검색/필터, 상태값, 이미지 업로드 |
| 4 | 텀블벅 MVP (포트폴리오) | 19주 | 실무 과정으로 완주: 인터뷰·PRD → Figma → PR·CI·테스트 → 풀스택(상태 관리·API·SQL·트랜잭션) → Vercel·Docker 배포 → 모니터링 → 실사용자 운영·개선 → 케이스 스터디 |

> 1~3단계는 개념을 익히는 **기초 앱**, 4단계는 포트폴리오에 넣을 수 있는 수준으로 만드는 **종합 프로젝트**입니다.

### "실제 서비스"의 의미
이 교재에서 만드는 서비스는 **실제 주소로 배포되어 실제 사람이 사용**합니다.
단, 결제는 **테스트 모드**입니다. 실제로 돈을 받으려면 코드 외에 사업자등록,
통신판매업 신고, PG사 계약, 이용약관/개인정보처리방침 등이 필요하며,
이는 교재 부록 "실제로 돈을 받으려면"에서 안내합니다.

## 시작하는 법 (독자용)
1. [`ROADMAP.md`](./ROADMAP.md)에서 전체 흐름을 훑어봅니다.
2. `docs/00-foundations/`부터 순서대로 진행합니다. 각 단계의 `tutorial/index.html`을
   브라우저에서 더블클릭해 열면 됩니다.
3. 막히면 각 단계 교재의 "🆘 막혔을 때"를 보고, 그래도 안 되면 `projects/` 폴더의
   정답 코드(단계별 체크포인트)와 내 코드를 비교합니다.
4. 해당 단계의 **완료 기준**을 모두 달성하기 전엔 다음 단계로 넘어가지 않습니다.

## 폴더 구조

```
tumblbug-study/
├── README.md          ← 지금 보고 있는 파일
├── ROADMAP.md          ← 전체 커리큘럼 (주차별 체크리스트)
├── AGENTS.md            ← AI 코딩 에이전트용 작업 지침 (교재 작성자용)
├── docs/                ← 단계별 교재 기획서(PLAN.md) + HTML 교재(tutorial/)
│   ├── 00-foundations/
│   ├── 01-linktree-clone/
│   ├── 02-buy-me-a-coffee-clone/
│   ├── 03-marketplace-clone/
│   └── 04-tumblbug-mvp/
├── projects/            ← 단계별 정답 코드 (실제로 실행해 검증된 코드)
└── prompts/             ← 교재 작성 당시 사용한 요청 프롬프트 (기록용)
```

`docs/`는 "설계도이자 교재", `projects/`는 "완성된 건물(정답)"이라고 생각하면 됩니다.

## 기술 스택

모든 프로젝트가 **같은 스택**을 씁니다. 프로젝트마다 새 도구를 배우면
"제품 개발" 자체를 배우는 시간이 줄어들기 때문에, 하나의 스택을 깊게 반복 사용합니다.

| 영역 | 도구 | 이유 |
|---|---|---|
| 프론트엔드 + 서버 로직 | Next.js (JavaScript, 서버 액션) | 화면과 서버 로직을 한 언어로 다룰 수 있어 초심자 진입장벽이 낮음 |
| 데이터베이스 | Neon (Postgres) | 무료 Postgres 호스팅. DB만 제공하므로 서버 로직·인증을 직접 짜며 백엔드 흐름을 배움 |
| DB 도구 (ORM) | Drizzle ORM + drizzle-kit | SQL과 모양이 거의 같아 SQL 감각을 유지하면서, 테이블 정의·마이그레이션을 코드로 관리 |
| 인증 | Better Auth (이메일/비밀번호) | 사용자·세션 테이블이 내 DB에 그대로 보여서 로그인 원리(해싱, 세션, 쿠키)를 눈으로 확인 가능 |
| 결제 | 토스페이먼츠 (테스트 모드) | 한국 문서화가 가장 잘 되어 있고 테스트 결제 무료 |
| 배포 | Vercel | Git 저장소 연결만 하면 자동 배포 |
| 코드 작성 | VSCode + 터미널(Git Bash) | 무료, 가장 널리 쓰이는 환경 |

> Supabase(DB + 인증을 대신 처리해주는 서비스)도 좋은 선택지지만, "대신 해주는 부분"이
> 곧 배워야 할 핵심(인증, 서버 로직)이라 판단해 1단계부터 직접 구현하는 조합을 택했습니다.

> 3단계부터 사진 저장소로 **Vercel Blob**을 씁니다.

**4단계에서 추가되는 도구** (포트폴리오 수준의 개발 과정을 위해)

| 영역 | 도구 | 이유 |
|---|---|---|
| 디자인 | Figma (무료) | 흐름도·와이어프레임·시안·디자인 시스템을 실무 도구로 |
| 입력 검사 | zod | 서버로 들어오는 값의 모양을 한 곳에서 선언하고 검사 |
| 상태 관리 | Zustand, TanStack Query | Zustand = 브라우저에만 있는 값(후원 단계 선택), TanStack Query = 브라우저에서 다루는 서버 데이터(무한 스크롤·찜·자동 새로고침) |
| 서버 운영 | Docker, AWS EC2 | 서버리스(Vercel) 밖에서 서버를 직접 띄우고 HTTPS·로그·재시작을 다뤄 봄 (요금 알림을 먼저 설정, 실습 후 삭제해 소액으로) |
| 부하 테스트 | k6 | 동시 결제 50건에도 초과 판매가 없는지 확인 |
| 테스트 | Vitest (단위), Playwright (흐름) | 모금 상태 계산 같은 핵심 로직과 결제 흐름을 자동으로 확인 |
| CI | GitHub Actions | PR마다 코드 검사·타입 검사·테스트·빌드를 자동 실행 |
| 모니터링 | Sentry (무료) | 운영 중 에러를 모으고 알림 |
| 예약 작업 | Vercel Cron | 마감된 프로젝트의 성공/실패를 하루 1번 확정 |

> **TypeScript는 3단계부터 도입합니다.** 1~2단계는 JavaScript로 개념에 집중하고, 3단계 1주차에 1단계 코드를
> TypeScript로 바꾸는 과정을 직접 겪으며 "타입이 실수를 미리 잡아주는" 경험을 합니다. (TypeScript 5, strict 모드)

## 학습 원칙

1. **한 단계씩만 진행** — 다음 단계 기능을 미리 넣지 않기 (스코프 크립 방지)
2. **막히면 "왜"부터 질문** — 코드만 복사하지 말고 "왜 이렇게 하는지" 교재의 💡 설명을 먼저 읽기
3. **완료 기준(Definition of Done) 달성 전엔 다음 단계로 안 넘어가기** — 각 PLAN.md 하단 참고
4. **매주 배운 것 3줄 요약** — 각 교재의 회고 양식에 기록
