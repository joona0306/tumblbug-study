# AWS 요금 안전장치와 EC2 실습 (16주차)

> 목표: 1단계에서 만든 Docker 이미지를 **AWS EC2 서버 1대**에서 직접 실행해 본다.
> 운영 주소는 계속 Vercel 이다. EC2 는 "서버를 직접 다뤄 보는" 실습 환경이고, **끝나면 지운다.**
>
> 마지막 확인: 2026-09-27 · AWS 콘솔 한국어 화면 · 무료 요금제(Free plan) 계정

## 0. 먼저 알아 둘 것 — 무료 요금제

2026-09 기준 새 AWS 계정은 가입할 때 요금제를 고른다 (AWS Free Tier 공식 페이지, 2026-09-27 확인).

| | 무료 요금제 (Free plan) — **이 교재의 선택** | 유료 요금제 (Paid plan) |
|---|---|---|
| 크레딧 | 가입 즉시 100달러 + 활동하면 최대 100달러 더 (최대 200달러, 6개월) | 같음 |
| 크레딧을 넘으면 | **청구되지 않는다** (유료로 바꾸지 않는 한) | 넘은 만큼 청구 |
| 끝나면 | 6개월 뒤 또는 크레딧을 다 쓰면 계정이 **닫힌다** (계속 쓰려면 유료로 전환) | 계속 |

→ 무료 요금제에서도 서버 요금은 **크레딧에서 빠져나간다.** 크레딧은 한정돼 있으니 쓰지 않는 자원은 바로 지운다.
조건은 자주 바뀐다 → 가입 화면과 공식 페이지의 문구를 직접 읽는다.

## 1. 요금 안전장치 (서버를 만들기 전에)

### ① 루트 계정 MFA
- **루트 사용자** = 가입한 이메일로 로그인하는 주인 계정. 모든 권한(계정 삭제·결제 변경)이 있다
- **MFA** = 비밀번호 + 휴대폰 인증 앱의 6자리 코드. 비밀번호가 새도 로그인할 수 없다
1. 휴대폰에 인증 앱 설치 (Google Authenticator / Microsoft Authenticator)
2. 오른쪽 위 계정 이름 → **보안 자격 증명** → **MFA 디바이스 할당** → 이름 `root-phone` · **인증 관리자 앱**
3. QR 코드를 앱으로 스캔 → 코드를 **연속 두 번** 입력 (30초마다 바뀐다) → **MFA 추가**
- ✅ 로그아웃 → 다시 로그인하면 6자리 코드를 묻는다
- 🆘 휴대폰을 잃어버리면 로그인이 어렵다 → 인증 앱의 백업 기능을 켜 둔다

### ② 요금 알림 (AWS Budgets)
검색창 **Budgets** → **예산 생성** → **템플릿 사용(간소화)**
| 예산 | 템플릿 | 알림 |
|---|---|---|
| `moa-zero-spend` | **제로 지출 예산** | 1센트라도 요금이 생기면 메일 |
| `moa-monthly-5usd` | **월별 비용 예산**, 5 USD | 5달러의 85%·100% 도달, 또는 이번 달 예상이 5달러를 넘으면 메일 |
- (있으면) **결제 기본 설정 → 알림 기본 설정 → AWS 프리 티어 알림 수신** 켜기
- ✅ Budgets 목록에 2개
- 무료 요금제는 크레딧을 넘어도 청구되지 않지만, 알림은 **크레딧이 새고 있다**는 신호다 → 메일이 오면 4번 체크리스트로 무엇이 남았는지 본다

### ③ 작업용 IAM 사용자
- **IAM** = "누가 무엇을 할 수 있는지" 정하는 곳. 루트는 금고에 두고, 실습은 작업용 사용자로 한다
1. (루트로 한 번) 계정 이름 → **계정** → **IAM 사용자 및 역할의 결제 정보 액세스** → 편집 → **IAM 액세스 활성화**
   - 안 하면 작업용 사용자에게 예산·요금 화면이 "권한 없음"으로 나온다
2. **IAM → 사용자 → 사용자 생성** → 이름 `moa-admin`
   - ☑ AWS Management Console 에 대한 사용자 액세스 권한 제공 → **IAM 사용자를 생성하고 싶음** (Identity Center 는 팀용)
   - 사용자 지정 암호 (루트와 다른 비밀번호)
   - **직접 정책 연결** → `AdministratorAccess` (실습을 막힘 없이 하기 위한 넓은 권한 → 대신 MFA 필수)
3. 완료 화면의 **콘솔 로그인 URL** (`https://12자리숫자.signin.aws.amazon.com/console`) 을 즐겨찾기
4. 그 URL 로 `moa-admin` 로그인 → **보안 자격 증명 → MFA 디바이스 할당** (이름 `moa-admin-phone`)
- ✅ 오른쪽 위에 `moa-admin @ 12자리숫자`, Budgets 에 예산 2개가 보인다
- 규칙: **루트는 결제·계정 설정 때만. 실습은 모두 `moa-admin`, 리전은 서울(ap-northeast-2)**

## 2. 무엇에 요금이 붙나

EC2 실습에서 크레딧이 빠져나가는 것은 아래 셋이다. **서버를 "중지"해도 2·3은 계속 나간다** — 그래서 실습이 끝나면 "종료(삭제)"한다.

| 자원 | 요금이 붙는 때 | 참고 |
|---|---|---|
| ① **EC2 인스턴스** (서버) | **실행 중**인 시간만큼 | 중지(Stop)하면 멈춘다. 가장 작은 서버(`t3.micro`) 기준 시간당 몇 센트 이하 |
| ② **공인 IPv4 주소** | 서버에 붙어 있거나, 고정 IP(Elastic IP)를 **만들어 두기만 해도** | 개당 시간당 **0.005달러** (한 달 약 3.6달러) — 2024년부터 유료 (AWS VPC 요금 페이지, 2026-09-27 확인) |
| ③ **디스크 (EBS 볼륨)** | **존재하는 동안** (서버를 중지해도) | 용량(GB)만큼. 서버를 종료할 때 함께 지워지게 설정한다 (기본값) |

- 정확한 금액은 리전·시점마다 다르다 → **Billing and Cost Management → 청구서(Bills)** 와 **크레딧**(Credits) 화면에서 실제로 빠진 금액을 본다
- 요금은 **몇 시간 늦게** 화면에 나타난다 → 실습 다음 날 한 번 더 확인한다

## 3. EC2 서버 만들기

### 구성
```
브라우저 ──HTTPS──▶ EC2 (t3.micro, Ubuntu 24.04)
                     caddy (80·443, 인증서 자동) ──▶ app (모아 이미지, 3000) ──▶ Neon "ec2" 브랜치 (DB)
                     이미지는 GitHub(GHCR)에서 받는다
```
| 항목 | 선택 | 이유 |
|---|---|---|
| 서버 | `t3.micro` (vCPU 2 · 메모리 1GiB) | 가장 작은 서버. 빌드는 GitHub 이 하고 서버는 받아서 실행만 한다 |
| OS | Ubuntu Server **24.04** LTS, 64비트(x86) | 자료가 가장 많다. 26.04 LTS 가 보여도 24.04 — 오래 검증됐다 (실습 뒤 지우는 서버라 긴 지원 기간보다 막힘 없는 쪽) |
| 디스크 | 16GiB gp3 | 이미지 몇 개를 보관할 여유 |
| 주소 | 탄력적 IP + `IP를-로-이은.sslip.io` | 도메인을 사지 않고 HTTPS 인증서를 받는다 |
| HTTPS | Caddy (리버스 프록시) | 인증서 발급·갱신이 자동 |
| DB | Neon 개발 프로젝트의 `ec2` 브랜치 (배포 워크플로가 만든다) | 1GiB 서버에 DB 까지 올리지 않는다 |

- **리버스 프록시** = 바깥 요청(80·443)을 먼저 받아 HTTPS 를 처리하고 안쪽 앱(3000)에 넘기는 문지기

### 3-1. 인스턴스 시작 (`moa-admin`, 서울 리전)
**EC2 → 인스턴스 시작**
| 항목 | 고를 것 |
|---|---|
| 이름 | `moa-ec2` |
| AMI | **Ubuntu Server 24.04 LTS (HVM), SSD Volume Type** · 아키텍처 **64비트(x86)** |
| 인스턴스 유형 | **t3.micro** — "모든 세대" 토글은 끈 채로 (옛 세대까지 보여 주는 스위치) |
| 키 페어 | **새 키 페어 생성** → `moa-ec2-key` · **ED25519** · **.pem** → 내려받은 파일을 내 사용자 폴더의 `.ssh` 폴더로 옮긴다 (없으면 만든다) |
| 네트워크 설정 → 편집 | 퍼블릭 IP 자동 할당 **활성화** · **보안 그룹 생성** `moa-ec2-sg` (아래 표) |
| 스토리지 | **16** GiB **gp3** |
| 고급 세부 정보 → 크레딧 사양 | **Standard** (Unlimited 면 CPU 를 오래 많이 쓸 때 추가 요금) |

AMI 목록에서 헷갈리는 것:
| 이름 | 고르나 |
|---|---|
| Ubuntu Server 24.04 LTS (HVM), SSD Volume Type · 프리 티어 사용 가능 | ✅ — HVM·SSD Volume Type 은 고르는 항목이 아니라 이름의 일부 |
| Ubuntu Pro … | ✗ 유료 지원 포함 |
| … with SQL Server … | ✗ Microsoft DB 라이선스 요금 (비싸다) |
| 아키텍처 Arm / 유형 `t4g` | ✗ Arm 서버 — 우리 x86 이미지가 돌지 않는다 |
- "프리 티어 사용 가능" = OS 에 추가 요금이 없다는 표시. 무료 요금제에서도 서버 요금은 **크레딧에서 빠진다**

보안 그룹 (= 서버 앞의 방화벽: 어떤 문(포트)을 누구에게 열까):
| 규칙 | 포트 | 소스 | 뜻 |
|---|---|---|---|
| SSH | 22 | 처음엔 **내 IP** → 3-4 에서 **위치 무관** | 서버 접속 (열쇠 파일로만 들어올 수 있다) |
| HTTP | 80 | 위치 무관 | 인증서 발급 확인 + https 로 넘기기 |
| HTTPS | 443 | 위치 무관 | 웹 접속 |

- ⚠️ `.pem` 파일은 채팅·GitHub 저장소·스크린샷에 올리지 않는다 (이 파일만 있으면 누구나 서버에 들어온다)

### 3-2. 고정 IP (탄력적 IP)
자동 IP 는 서버를 껐다 켜면 바뀐다 → HTTPS 주소를 고정하려면 고정 IP.
1. **EC2 → 네트워크 및 보안 → 탄력적 IP → 탄력적 IP 주소 할당** → 할당
2. 그 IP 를 체크 → 목록 위의 **탄력적 IP 주소 연결** 버튼 (작업 메뉴 안이 아니다) → 리소스 유형 **인스턴스** → `moa-ec2` → 연결
   - 작업 메뉴의 **연결 해제**·**릴리스**는 누르지 않는다 (릴리스 = 삭제, 실습 뒤 정리할 때)
- ✅ 인스턴스의 **퍼블릭 IPv4 주소** = 탄력적 IP
- Name·역방향 DNS 가 비어 있는 것은 정상 (메모용 이름표, 메일 서버용 설정)

### 3-3. 서버 준비 (한 번)
내 컴퓨터(Git Bash, 프로젝트 폴더)에서:
```
ssh -i ~/.ssh/moa-ec2-key.pem ubuntu@탄력적IP 'bash -s' < deploy/ec2-setup.sh
```
- 처음 접속하면 서버 지문을 저장할지 묻는다 → `yes`
- 하는 일: 스왑 1GB(메모리가 모자랄 때 대비) · Docker 설치(공식 저장소) · 로그 크기 제한 · 배포 폴더 `~/moa`
- ✅ 마지막에 `Docker version …`, `Docker Compose version …`, `/swapfile … 1024M`

### 3-4. 배포 설정 (GitHub)
배포 워크플로(`.github/workflows/ec2.yml`)가 쓰는 값. 저장소 **Settings → Environments → New environment** `ec2`:
| 종류 | 이름 | 값 |
|---|---|---|
| Secret | `EC2_SSH_KEY` | `.pem` 파일 내용 전체 (메모장으로 열어 `-----BEGIN` 부터 `END …-----` 까지) |
| Secret | `EC2_BETTER_AUTH_SECRET` | 새 무작위 글자 — `node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"` (운영 값과 **다르게**) |
| Variable | `EC2_HOST` | 탄력적 IP (예: `3.34.218.244`) |

저장소 **Settings → Secrets and variables → Actions → Variables** 에 `EC2_ENABLED` = `true`

보안 그룹 `moa-ec2-sg` 의 SSH(22) 소스를 **위치 무관(0.0.0.0/0)** 으로 바꾼다 — GitHub Actions 는 매번 다른 주소에서 접속하기 때문
- 대신 열쇠 파일(.pem) 없이는 들어올 수 없다 (Ubuntu 는 비밀번호 로그인이 꺼져 있다)
- 실무에서는 SSH 를 아예 닫고 AWS 전용 접속 도구(Systems Manager)를 쓰기도 한다 — 이 실습은 끝나면 서버를 지우므로 단순한 방법을 쓴다

### 3-5. 배포와 롤백
- **main 에 합치면**: CI/CD 가 성공한 뒤 자동으로 EC2 배포 (Actions → **EC2**)
  - 이미지 빌드 → GHCR → EC2 DB 마이그레이션 → 서버에서 바꿔 끼우기(`deploy/deploy.sh`) → HTTPS 주소에 연기 테스트
- **손으로**: Actions → **EC2** → **Run workflow** (image_tag 비움 = 지금 main)
- **롤백 연습**: Run workflow 의 image_tag 에 **이전 커밋 SHA 전체**를 넣는다 → 그 이미지로 되돌아간다
- **자동 롤백**: 새 이미지가 120초 안에 healthy(= `/api/health` 200)가 안 되면 서버가 이전 이미지로 되돌리고, 워크플로는 실패(빨간불)로 끝난다
- ✅ `https://탄력적IP를-로-이은.sslip.io` 가 열리고, `/api/health` 의 `commit` 이 방금 배포한 커밋

🆘 막혔을 때
| 증상 | 원인 → 해결 |
|---|---|
| 배포의 "SSH 준비"·"설정 파일 올리기"가 실패 (`Connection timed out`, `exit code 1`) | 보안 그룹 SSH(22) 소스가 아직 "내 IP" → 위치 무관으로 |
| 보안 그룹을 고치기 **전에** PR 을 머지해서 배포가 실패했다 | 보안 그룹을 고친 뒤 Actions → 실패한 **EC2** 실행 → **Re-run jobs → Re-run failed jobs** (이미지는 이미 올라가 있어서 배포만 다시 한다, 몇 분) |
| `Permission denied (publickey)` | `EC2_SSH_KEY` 에 .pem 내용이 일부만 들어감 → BEGIN~END 전체를 다시 |
| 주소는 열리는데 인증서 경고 | 인증서 발급 전(1~2분) — 80·443 이 열려 있는지 보안 그룹 확인 |
| `unhealthy` 로 롤백됨 | 워크플로 로그의 "최근 로그" 부분에 앱이 멈춘 이유 (환경 변수 등) |

## 4. 실습 후 삭제 체크리스트 (반드시)

서울 리전(ap-northeast-2)에서, `moa-admin` 으로:
- [ ] **EC2 → 인스턴스** → 실습 서버 선택 → **인스턴스 상태 → 인스턴스 종료(삭제)** → 상태가 "종료됨"
  - "종료됨" 인스턴스가 목록·대시보드에 **1시간쯤 남아 있다가** 저절로 사라진다 — 이미 삭제된 것이고 요금도 없다 (정상)
- [ ] **EC2 → 탄력적 IP** → 목록이 비었나. 남아 있으면 **연결 해제 → 탄력적 IP 주소 릴리스** (안 지우면 계속 과금)
- [ ] **EC2 → 볼륨** → 목록이 비었나 (종료와 함께 지워진다. 남았으면 삭제)
- [ ] **EC2 → 스냅샷**, **AMI** → 만든 적 없으면 비어 있다
- [ ] **EC2 → 보안 그룹** → 실습용(`moa-ec2-sg`) 삭제 (요금은 없지만 정리)
- [ ] **EC2 → 키 페어** → 실습용 삭제, 내 컴퓨터의 `.pem` 파일도 삭제
- [ ] GitHub: 변수 `EC2_ENABLED` 를 `false` 로 (서버가 없는데 배포가 돌지 않게) · **Settings → Environments → `ec2`** 삭제 (SSH 키·주소)
