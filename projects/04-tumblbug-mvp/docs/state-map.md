# 상태 관리 지도 — 모아

> **상태(state)**: 시간이 지나면서 바뀌는 값. 화면은 상태를 그린 그림이다.
> 상태마다 **어디에 두는지**를 먼저 정하면, "이 값이 왜 새로고침하면 사라지지?" 같은 버그를 설계 단계에서 막을 수 있다.
> 새 기능을 만들 때마다 이 표에 한 줄씩 추가한다. (5주차 작성, 이후 주차마다 갱신)

## 어디에 둘지 고르는 질문 (위에서부터 차례로)

1. **서버(DB)에 저장해야 하나?** (다른 사람도 보거나, 기기를 바꿔도 남아야 함) → **서버 상태**
   - 처음 화면은 서버 컴포넌트가 DB에서 읽어 그린다
   - 그 뒤 브라우저에서 이어서 가져오거나 바꾸면 → **TanStack Query**
2. **주소를 공유하거나 뒤로가기 했을 때 그대로여야 하나?** → **URL 상태** (`?category=living`)
3. **폼 제출 결과·에러 메시지인가?** → **폼 상태** (`useActionState`, `useFormStatus`)
4. **여러 화면(페이지)이 함께 쓰는데 서버에는 없는 값인가?** → **Zustand** (필요하면 `persist`로 새로고침 유지)
5. **앱 전체에 하나뿐이고 자주 안 바뀌나?** → **React Context**
6. **그 외: 한 컴포넌트 안에서만 쓰는 값** → **`useState`**

## 이 앱의 상태

| 상태 | 종류 | 어디에 | 주차 | 이유 |
|---|---|---|---|---|
| 프로젝트·리워드·후원 목록, 모인 금액 | 서버 상태 | DB → 서버 컴포넌트 | 8 | 모두가 같은 값을 봐야 함 |
| 목록의 카테고리·상태 필터, 정렬 | URL 상태 | `searchParams` | 8~9 | 공유·새로고침·뒤로가기해도 유지 |
| 목록 다음 페이지 (무한 스크롤) | 서버 상태 (브라우저에서 이어서) | TanStack Query `useInfiniteQuery` + `/api/projects?cursor=` | 9 | 이미 받은 페이지를 캐시하고, 이어서만 가져옴 |
| 찜 여부·내 찜 개수 | 서버 상태 (브라우저에서 바꿈) | TanStack Query `useMutation` (낙관적 업데이트) | 12 | 카드·상세·헤더가 같은 캐시를 봄, 실패 시 되돌림 |
| 대시보드 새 후원 | 서버 상태 | TanStack Query `refetchInterval` (15초) → 새 후원이 오면 `router.refresh()` | 12~13 | 새로고침 없이 새 후원 확인, 모금 현황 숫자도 함께 갱신 |
| 대시보드 모금 현황·표 | 서버 상태 | DB → 서버 컴포넌트 (SQL 집계) | 13 | 저장하지 않고 후원 기록에서 매번 계산 |
| 대시보드에서 고른 프로젝트 | URL 상태 | `?project=3` | 12 | 새로고침·공유해도 같은 프로젝트 |
| 후원 단계에서 고른 리워드·수량·추가 후원금·배송지 | 클라이언트 상태 (여러 페이지) | Zustand + `persist` (sessionStorage) | 10 | 결제 전까지 서버에 없음, 단계 이동·새로고침에도 유지, 결제 완료 시 비움 |
| 현재 후원 단계 (1·2·3) | URL 상태 | `?step=2` | 10 | 뒤로가기가 이전 단계로 가게 |
| 프로젝트 등록 폼 에러, 제출 중 표시 | 폼 상태 | `useActionState`, `useFormStatus` | 7 | 서버 액션 결과를 그대로 보여줌 |
| 토스트 알림 | 앱 전체 값 | React Context | 12 | 어디서든 띄움, 앱에 하나 |
| 화면 테마 (시스템·라이트·다크) | 사용자 설정 (기기별) | 쿠키 → 레이아웃이 읽어 `<html data-theme>` | 14 | 서버가 첫 화면부터 맞는 색으로 그린다. localStorage 는 서버가 못 읽어 켤 때 색이 번쩍 바뀐다 |
| 퍼널 기록 (상세→리워드→배송지→결제 요청→완료) | 서버 상태 (운영 지표) | DB `funnel_event` + 익명 방문자 쿠키 `moa-vid` | 15 | 화면에는 안 보이는 값. 브라우저는 앞 세 단계만 알리고, 결제 두 단계는 서버가 기록 |
| 상세 탭 선택, 수량 +/− 입력 중 값, 메뉴 열림 | 화면 임시 상태 | `useState` | 8~10 | 한 컴포넌트 안에서만 씀 |
| 로그인 사용자 | 서버 상태 | 쿠키(세션) → 서버에서 읽기 | 7 | 브라우저 상태로 복사해 두지 않음 (어긋나기 쉬움) |

## 하지 않기로 한 것

- 서버 데이터를 Zustand에 복사해 두기 → 서버 값과 어긋난다 (그래서 찜은 TanStack Query)
- 필터를 `useState`로 들고 있기 → 새로고침·공유 시 사라진다 (그래서 URL)
- 로그인 사용자 정보를 Context에 넣어 두기 → 로그아웃·만료 시 어긋난다 (그래서 매번 서버에서 확인)

관련 결정 기록: ADR-004 (브라우저 쪽 상태 도구 선택)
