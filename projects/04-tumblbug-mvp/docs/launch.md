# 운영 시작 — 실제 사용자 받기 (17주차)

> 목표: **창작자 1명**의 프로젝트를 운영 사이트에 올리고, **지인 3~5명**이 테스트 결제로 후원하게 한다.
> 이 교재의 작성자는 **오프라인 스터디**에서 사용자를 모집했다 — 아래 순서는 그 경험을 바탕으로 한다.

## 그림 먼저
```
창작자 1명 ──프로젝트·리워드 등록──▶ 모아 (운영 사이트) ◀──테스트 결제로 후원── 지인 3~5명
                                        │
나 (운영자) ◀── Sentry 알림 · 가동 감시 · 매일 운영 점검 · 퍼널 · 의견(설문지)
```
- 지금까지는 **내가 만들고 내가 써 봤다.** 이번 주부터는 **남이 쓰는 것을 지켜본다** — 내가 예상하지 못한 곳에서 막힌다
- 15주차에 만든 알림·점검 도구가 처음으로 "진짜 사용자" 앞에서 일한다

## 1. 운영 시작 전 점검 (운영자)

- [ ] 운영 사이트에서 쓸 **관리자 계정**이 있다 (`docs/accounts.md` — 운영 계정 찾기·관리자 만들기)
- [ ] 연습하면서 만든 **테스트 프로젝트를 숨겼다** (관리자 화면 → 숨기기. 지우지 않고 숨기면 후원 기록은 남는다)
- [ ] **의견 보내기 설문지**를 만들고 주소를 넣었다 (아래 2번)
- [ ] 화면 위 **학습용 안내 띠**, 화면 아래 **개인정보 처리 안내**가 보인다 → `/privacy` 내용을 한 번 읽어 본다
- [ ] 알림이 살아 있다: Sentry 알림(`operations.md` 1번), UptimeRobot **Up**(2번), GitHub Actions **Ops check** 가 최근에 성공(3번)
- [ ] 내 관리자 계정이 아닌 **두 번째 계정**으로 운영 사이트에서 테스트 결제 1건이 끝까지 된다 (창작자와 후원자는 다른 계정이어야 한다 — 내 프로젝트에는 후원할 수 없다)

## 2. 의견 보내기 — Google 설문지

1. Google 설문지(forms.google.com) → **새 설문지** → 제목 `모아 — 써 보신 의견을 들려주세요`
2. 질문 (짧게 — 2분 안에 끝나게)
   | 질문 | 형식 |
   |---|---|
   | 어떤 역할로 써 보셨나요? (창작자 / 후원자 / 둘러보기만) | 객관식 |
   | 어디까지 해 보셨나요? (가입 / 프로젝트 보기 / 리워드 선택 / 배송지 / 결제 완료) | 체크박스 |
   | **가장 헷갈리거나 막혔던 곳은 어디였나요?** | 장문형 (가장 중요한 질문) |
   | 좋았던 점이 있다면? | 장문형 |
   | 쓰는 기기 (휴대폰 / 컴퓨터) | 객관식 |
   | (선택) 답장을 받을 연락처 | 단답형 |
3. 위쪽 **설정** 탭 → **응답** 펼치기 (개인정보를 필요 이상으로 받지 않고, 로그인 없이 답하게)
   - **이메일 주소 수집** → **수집하지 않음**
   - **응답 횟수 1회로 제한** → **끔** (켜면 Google 로그인을 해야 답할 수 있다)
4. 오른쪽 위 **게시** → 응답자: **링크가 있는 모든 사용자** → **응답자 링크 복사** (URL 단축 켜기 → `https://forms.gle/…`)
   - 주소창의 `…/edit` 주소는 **편집용** — 넣으면 안 된다
   - ✅ 복사한 링크를 **시크릿 창**(Ctrl+Shift+N)에서 열어 로그인·이메일 없이 열리는지
   - (2026-09 화면 기준. 예전 화면은 "보내기 → 링크 → URL 단축")
5. Vercel → 모아 프로젝트 → **Settings → Environment Variables** → `NEXT_PUBLIC_FEEDBACK_URL` = 복사한 주소
   - 환경: **Production** · 종류(Type): **Config** — **Secret 으로 넣으면 링크가 안 보인다** (Secret 은 GitHub Actions 빌드 때 값이 오지 않는다, 14주차). 공개돼도 되는 값이라 괜찮다
6. **다시 배포해야 반영된다** — `NEXT_PUBLIC_` 값은 빌드할 때 화면 코드에 새겨지기 때문 (1단계 Docker 에서 배운 것과 같다)
   - 아무 PR 이나 합치면 새로 배포된다. 급하면 Vercel → Deployments → 최신 배포 → **Redeploy**
- ✅ 운영 사이트 맨 아래 **의견 보내기**를 누르면 설문지가 새 탭으로 열린다

## 3. 스터디에서 소개하기 (5분)

준비: 운영 사이트 주소를 **QR 코드**로 — Chrome 에서 주소창 오른쪽 **공유 → QR 코드 만들기** → 다운로드해서 화면에 띄우거나 인쇄

말할 것:
1. **무엇인가** — "제가 교재를 따라 만든 크라우드펀딩 서비스예요. 실제 운영을 연습하려고 여러분께 써 달라고 부탁드려요"
2. **돈이 안 나간다** — "결제는 모두 **테스트**예요. 결제창에서 카드사를 골라 진행해도 실제로 청구되지 않아요"
3. **개인정보** — "배송지는 **가짜 주소**여도 돼요. 무엇을 저장하는지는 화면 맨 아래 '개인정보 처리 안내'에 있고, **스터디가 끝나면 모두 지워요**"
4. **부탁** — "막히는 곳이 있으면 그게 제일 소중한 정보예요. 맨 아래 '의견 보내기'에 적어 주세요"
5. **(창작자 1명에게)** 따로 시간을 잡고 아래 4번 안내문을 보낸다

## 4. 창작자 안내문 (보낼 메시지 예시)

> 모아에 프로젝트를 올려 주셔서 고마워요! 준비물과 순서예요.
>
> **준비물**
> - 제목(50자 이하) · 한 줄 요약(80자 이하) · 소개글
> - 목표 금액: **1만 원 ~ 1억 원** · 마감일: **내일 ~ 60일 뒤**
> - 대표 사진 1장 (휴대폰 사진 그대로 — 올릴 때 알아서 줄여요)
> - 리워드(최대 10개): 이름, 가격(**1,000원 ~ 100만 원**), 한정 수량(비우면 무제한), 전달 예정 달, 배송이 필요한지
>
> **순서**
> 1. 주소 접속 → **회원가입**
> 2. 위쪽 **프로젝트 올리기** → 내용과 사진 → 등록
> 3. 등록하면 바로 나오는 수정 화면 **아래쪽 리워드 칸**에서 **리워드 추가** (리워드가 있어야 후원자가 고를 수 있어요)
> 4. **스튜디오**에서 모인 금액·후원자·배송지를 볼 수 있어요 (배송지는 창작자인 나만 봐요)
>
> 진짜 돈은 오가지 않아요. 써 보면서 불편한 곳을 '의견 보내기'로 알려 주세요!

## 5. 후원자 안내 (단톡방·화면에 띄울 문구)

> 1. QR 코드로 접속 → **회원가입**
> 2. **프로젝트 둘러보기** → 마음에 드는 프로젝트 → **후원하기**
> 3. 리워드 고르기 → (배송이 필요한 리워드면) 배송지 — **가짜 주소 OK**
> 4. **결제하기** → 토스 **테스트 결제창**에서 진행 (실제 청구 없음)
> 5. **내 후원 내역**에서 확인 · 다 쓰고 나면 맨 아래 **의견 보내기** 🙏

## 6. 운영하는 동안 (17~20주)

- **매일**: Ops check 실패 메일 · Sentry 알림 · UptimeRobot 알림이 없었나 (있으면 그날 처리 → 장애 회고)
- **매주**: `npm run ops:check` 대신 GitHub **Actions → Ops check → Run workflow** 결과로 **퍼널**을 본다 · 설문지 응답을 읽는다
- 한 주가 끝나면 **운영 일지**를 쓴다 (`docs/04-tumblbug-mvp/templates/09-ops-log.md`) → 18주차 개선 우선순위의 재료
- 사용자가 막혔다고 하면: **그 자리에서 고쳐 주지 말고 먼저 적는다** (어느 화면에서, 무엇을 하려다, 무엇을 봤나) — 한 명이 막힌 곳은 다른 사람도 막힌다

## 7. 스터디가 끝나면 (약속 지키기)

`/privacy` 에 "스터디가 끝나면 모든 계정과 후원 기록을 지운다"고 적었다 → 20주차 케이스 스터디 뒤에 운영 DB 의 사용자 데이터를 지운다 — `npm run ops:end` (먼저 세기만, `--confirm=DB이름` 으로 지우기 — `docs/case-study/week20-case-study.md` "운영 종료"). 설문지 응답도 함께 정리한다.
