# 1단계: Linktree 클론 — 교재 기획서

**교재 제작 상태**: 기획 확정 / 정답 코드 작성 전
**학습 기간**: 1개월 (1~4주차)
**학습 목표**: 기획→디자인→개발→배포→운영 전체 사이클을 짧고 작게 1회 완주하기.
그 과정에서 로그인이 실제로 어떻게 동작하는지(해싱, 세션, 쿠키)를 직접 구현하며 이해하기

## 선수 지식
- 0단계(기초) 완료: 터미널 기본 명령어, HTML/CSS/JS 기초, Git으로 커밋·푸시, Vercel 배포 1회 경험
- 계정: GitHub, Neon, Vercel

## 문제 정의
> SNS 프로필에는 링크를 하나만 넣을 수 있다. 여러 링크(유튜브, 인스타, 블로그 등)를
> 한 페이지에 모아 보여주고 싶은 사람을 위한 서비스.

## 기능 범위

| 포함 | 제외 |
|---|---|
| 회원가입/로그인/로그아웃 (이메일 + 비밀번호) | 소셜 로그인, 이메일 인증, 비밀번호 찾기 |
| 링크 추가/수정/삭제 | 링크 순서 드래그 정렬 |
| 공개 페이지 (해당 사용자의 링크 목록 노출) | 테마/커스텀 디자인 |
| 링크 개수 3개 제한 (무료 버전 흉내, 서버에서 검사) | 실제 결제로 무제한 풀기 |

## 화면 목록
1. 로그인 / 회원가입
2. 링크 관리 화면 (로그인한 본인만 보는 대시보드)
3. 공개 페이지 (`/사용자이름` 형태로 누구나 접근 가능)

## 데이터 구조
```
user     : id, email, name, username, ...  ← Better Auth가 만드는 표 + username 필드 추가
session  : id, user_id, token, expires_at  ← 로그인 상태 기록 (Better Auth)
account  : id, user_id, password(해시)     ← 비밀번호가 암호화되어 저장되는 곳 (Better Auth)
link     : id, user_id, title, url, position, created_at
```
- 관계: `user` 1 : N `link` (한 사용자가 여러 링크를 가짐)
- 처음 초안의 `order` 컬럼은 SQL 예약어(ORDER BY)와 겹쳐 오류를 부르기 쉬워서 `position`으로 바꿈
  → 교재에서 "왜 이름을 바꿨는지"를 설명하는 소재로 활용
