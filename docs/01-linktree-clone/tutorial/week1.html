1주차 · 코드 없음 · 5단계

기획과 디자인: 무엇을, 누구를 위해, 어떻게 보이게 만들까

이번 주에는 코드를 한 줄도 쓰지 않습니다. 대신 "무엇을 만들지"를 글과 그림으로 정합니다. 개발자가 가장 많이 하는 실수는 만들 것을 정하지 않고 바로 코드부터 쓰는 것입니다.

💡 왜 기획부터 하나요?

집을 지을 때 설계도 없이 벽돌부터 쌓으면, 다 쌓은 뒤에야 "문이 없네?"를 깨닫게 됩니다. 코드는 벽돌이고 기획은 설계도입니다. 설계도는 지우개로 고치면 되지만, 코드를 고치려면 몇 시간이 걸립니다.

이번 주 결과물은 기획 문서 1개(문제·범위·지표·디자인 결정) + 와이어프레임 3장입니다. 작업 폴더에 기획용 폴더를 만들어 모아 두세요.

code 파일이름은 VSCode로 그 파일을 열라는 명령어입니다. 파일이 없으면 새로 만들어 줍니다.

1경쟁 서비스 3개 직접 써보기

우리가 만들 것과 비슷한 서비스를 사용자 입장에서 직접 가입하고 써봅니다. 아래 세 개를 추천합니다.

서비스주소특징

인포크링크link.inpock.co.kr한국 인플루언서가 많이 쓰는 서비스

각 서비스에서 이렇게 해보세요.

  1. 가입하고 링크를 2~3개 등록해서 내 페이지를 만든다
  2. 화면마다 캡처한다 (Win + Shift + S) — 가입 화면, 관리 화면, 공개 페이지
  3. 휴대폰으로 내 공개 페이지 주소를 열어본다 (실제 방문자가 보는 화면)
  4. 아래 표를 기획.md에 복사해서 채운다
📖 용어 풀이경쟁 서비스 분석: 이미 있는 서비스를 써보며 "사람들이 당연하게 기대하는 기능"과 "아쉬운 점"을 찾는 일입니다. 똑같이 베끼려는 게 아니라, 기준점을 잡으려는 것입니다.
2문제 정의와 기능 목록 정리하기

① 한 문장으로 문제 정의

"누가, 어떤 불편을 겪고, 우리는 그걸 어떻게 해결하는가"를 한 문장으로 씁니다.

② 기능 목록: "포함"보다 "제외"가 더 중요하다

비교표에서 본 기능을 모두 만들고 싶어지겠지만, 한 달 안에 끝내려면 이번에 안 만들 것을 먼저 정해야 합니다. 포함 칸에는 "이게 없으면 서비스가 성립하지 않는 것"만 넣으세요.

📖 용어 풀이
  • 스코프(Scope, 범위): 이번에 만들 것의 경계선입니다.
  • 스코프 크립(Scope creep): 만드는 도중에 "이것도 넣자"가 계속 늘어나 끝나지 않는 현상. 초심자 프로젝트가 실패하는 1순위 원인입니다.
  • MVP: Minimum Viable Product, "쓸 수 있는 최소한의 제품". 포함 칸이 곧 우리의 MVP입니다.
💡 왜 링크를 3개로 제한하나요?실제 서비스들이 "무료는 N개까지"처럼 제한을 두는 방식을 흉내 낸 것입니다. 이 제한을 제대로 구현하려면 "화면에서 막기"와 "서버에서 막기"의 차이를 이해해야 해서, 3주차의 중요한 학습 소재가 됩니다.

③ 성공 지표: "잘 되고 있다"를 숫자로 정하기

만들고 나서 "괜찮은 것 같은데?"로 끝나면 무엇을 고쳐야 할지 알 수 없습니다. 그래서 만들기 전에 무엇을 보면 성공인지 정해 둡니다. 좋은 지표는 서비스의 핵심 가치를 사용자가 실제로 누렸는지를 보여줍니다.

💡 왜 "가입자 수"가 아닌가요?가입자 수는 홍보만 하면 올라갑니다. 하지만 가입하고 아무것도 안 했다면 서비스가 쓸모 있었다고 볼 수 없죠. "핵심 행동을 한 사람의 비율"이 제품이 제 역할을 하는지 더 잘 보여줍니다. 이 숫자는 4주차에 실제 데이터로 계산하고, 개선할 곳을 찾는 데 씁니다.
3와이어프레임 3장 그리기

와이어프레임은 화면의 "뼈대 스케치"입니다. 색, 글꼴, 예쁜 디자인은 모두 빼고 무엇이 어디에 있는지만 박스와 글자로 그립니다.

  • 도구: 종이와 펜을 추천합니다. 컴퓨터로 그리고 싶다면 excalidraw.com(무료, 가입 불필요)
  • 규칙: 흑백, 한 장에 5~10분. 잘 그리려고 하지 마세요.
  • 종이에 그렸다면 사진을 찍어 my-links-plan 폴더에 저장하세요.

이 교재에서 만들 화면 3개의 예시입니다. 똑같이 그릴 필요는 없고, 비교표를 보고 내 생각대로 그려도 됩니다.

그릴 때 스스로에게 이 질문들을 던져 보세요.

  • 이 화면에 처음 온 사람은 무엇을 가장 먼저 봐야 하나?
  • 버튼을 누르면 어느 화면으로 가나? (화살표로 표시)
  • 링크가 0개일 때, 3개로 꽉 찼을 때 화면은 어떻게 보이나?
4디자인 결정: 색·글꼴·모양 정하기

와이어프레임이 "무엇이 어디에"라면, 디자인은 "어떻게 보여서 사용자가 헷갈리지 않게 할지"를 정하는 일입니다. 예쁘게 꾸미는 것보다 일관된 결정이 먼저예요.

① 기억할 원칙 4가지

원칙뜻우리 서비스에서
위계중요한 것일수록 크고 진하게공개 페이지에서 가장 눈에 띄는 건 링크 버튼
여백관련 있는 것은 가깝게, 다른 것은 멀게링크 목록 카드와 "새 링크 추가" 카드를 떨어뜨리기
일관성같은 역할은 같은 모양"실행" 버튼은 모두 파란색, "위험한 버튼(삭제)"은 모두 빨간 테두리
대비글자와 배경의 밝기 차이가 충분해야 읽힘흐린 회색 글씨도 기준(4.5:1) 이상으로

② 무드보드: 참고할 화면 고르기

1단계에서 캡처한 경쟁 서비스 화면 중 좋았던 것 3장을 골라 my-links-plan 폴더에 모으고, 각각 "왜 좋았는지"를 한 줄씩 적으세요. (예: "버튼이 둥글어서 누르기 쉬워 보임")

③ 디자인 결정표 쓰기

색은 4~6개면 충분합니다. 결정한 값은 2주차에 CSS 변수로 그대로 옮기게 됩니다.

④ 대비 확인하기

색을 바꿨다면 WebAIM Contrast Checker에 글자색과 배경색을 넣어 4.5:1 이상인지 확인하세요. 이 교재 기본값은 작성자가 계산해 두었습니다.

📖 용어 풀이디자인 토큰: 색, 간격, 모서리처럼 디자인 결정을 이름 붙인 값으로 정리한 것. 위 표의 --primary 같은 CSS 변수가 바로 디자인 토큰입니다. 결정을 한 곳에 모아두면 나중에 색을 바꿀 때 한 줄만 고치면 됩니다.
