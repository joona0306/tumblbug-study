3로그인 설정 + 테이블 만들기

① 먼저 그림으로: 어떤 표(테이블)가 필요한가

1주차에 적은 데이터 구조를 실제 DB 표로 옮깁니다. 로그인에 필요한 표 4개는 Better Auth가 설계도를 만들어주고, 링크 표 1개는 우리가 직접 설계합니다.

📖 용어 풀이
  • 테이블(표): 엑셀 시트처럼 칸(컬럼)과 줄(행)로 된 데이터 묶음. 링크 1개 = link 표의 1줄.
  • 기본 키(Primary Key): 각 줄을 구별하는 고유 번호(id). 주민등록번호처럼 겹치지 않습니다.
  • 외래 키(Foreign Key): 다른 표의 id를 적어 둔 칸. link의 user_id에 사용자 id를 적으면 "이 링크의 주인은 이 사람"이 됩니다.
  • 세션: "이 사람은 로그인한 상태"라는 기록. 로그인하면 session 표에 한 줄이 생기고, 그 표의 token이 브라우저 쿠키로 전달됩니다.
💡 비밀번호는 왜 user가 아니라 account 표에 있나요?한 사람이 "이메일+비밀번호", "구글 로그인"처럼 여러 로그인 수단을 가질 수 있게 하려는 설계입니다. 우리는 이메일+비밀번호(provider_id = credential) 한 가지만 씁니다.

  4. Neon → Tables → account 표를 열어 password 칸을 보세요. password123이 아니라 알아볼 수 없는 긴 문자열이 들어 있습니다. 이게 해시입니다.
📖 용어 풀이해시(Hash): 원래 값으로 되돌릴 수 없게 뒤섞은 값입니다. 로그인할 때는 입력한 비밀번호를 같은 방식으로 뒤섞어서 저장된 값과 같은지만 비교합니다. 그래서 DB가 털려도 비밀번호 원문은 알 수 없습니다.

4회원가입·로그인 화면 만들기

① 먼저 그림으로: 가입하고 로그인하면 무슨 일이 일어나나

📖 용어 풀이
  • 쿠키: 서버가 브라우저에 맡겨두는 작은 메모. 브라우저는 같은 사이트에 요청할 때마다 이 메모를 자동으로 함께 보냅니다. 놀이공원 입장 팔찌와 같아요.
  • 서버 액션: 폼을 제출하면 서버에서 실행되는 함수입니다. 파일 맨 위에 "use server"를 쓰면 그 파일의 함수들이 서버 액션이 됩니다. 브라우저는 함수의 내용을 볼 수 없고 결과만 받습니다.
  • "use client": 이 파일은 브라우저에서 실행된다는 표시입니다. 입력 중 상태, 버튼 비활성화처럼 화면이 즉시 반응해야 하는 부분에 씁니다.
