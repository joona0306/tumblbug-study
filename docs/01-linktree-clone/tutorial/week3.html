링크 관리와 공개 페이지

서비스의 핵심 기능을 만듭니다. 이번 주의 진짜 주제는 "서버는 아무도 믿지 않는다"입니다. 화면은 사용자가 마음대로 조작할 수 있으므로, 중요한 규칙은 반드시 서버에서 다시 검사합니다.

📖 용어 풀이CRUD: 데이터를 다루는 네 가지 기본 동작의 앞글자입니다. Create(추가), Read(읽기), Update(수정), Delete(삭제). 거의 모든 서비스가 이 네 가지의 조합입니다.

먼저 그림으로: 링크 추가 버튼을 누르면

1링크 추가하고 목록 보기

링크 규칙(최대 개수, 입력 검사)을 한 파일에 모아 둡니다. 화면과 서버가 같은 숫자를 쓰게 하려는 것입니다.

💡 왜 http/https 주소만 허용하나요?링크 주소 칸에 javascript:로 시작하는 값을 넣으면, 공개 페이지에서 그 링크를 누른 방문자의 브라우저에서 악성 코드가 실행될 수 있습니다. 공개 페이지는 남이 보는 곳이므로 안전한 주소만 받습니다.

링크 추가 서버 액션입니다. 위 그림의 ①~⑤가 순서대로 들어 있어요.

📖 코드 읽는 법
  • db.select({ total: count(), ... }).from(link).where(eq(link.userId, user.id)) = "link 표에서 주인이 나인 줄의 개수를 세줘". SQL로 쓰면 SELECT count(*) FROM link WHERE user_id = '내 id'입니다.
  • revalidatePath("/dashboard"): "이 주소의 화면을 최신 데이터로 다시 그려줘". 이게 없으면 저장은 됐는데 화면에는 안 보일 수 있습니다.

대시보드 폴더 안에 추가 폼 컴포넌트를 만듭니다. 파일 이름이 page.js가 아니라서 주소가 생기지 않고, 대시보드 안에 끼워 넣는 부품으로만 쓰입니다.

대시보드를 "내 링크 목록 + 추가 폼"으로 바꿉니다.

app/globals.css 맨 아래에 목록용 스타일을 추가합니다.

✅ 여기까지 됐는지 확인하는 법
  1. 제목 "나쁜 링크", 주소 javascript:alert(1) → "주소는 http:// 또는 https:// 로 시작해야 합니다."
  2. 진짜 주소로 링크 3개 추가 → 목록에 순서대로 보이고, 추가할 때마다 입력칸이 비워진다
  3. 3개가 되면 "3 / 3개 사용 중"이 되고, 추가 폼 대신 "무료 버전은 링크를 3개까지…" 안내가 보인다

2링크 수정하고 삭제하기

수정과 삭제에서 가장 중요한 한 가지: "이 링크가 요청한 사람의 것인가?"를 서버에서 확인하는 것입니다.

💡 왜 id만으로 수정하면 안 되나요?

수정 폼에는 "몇 번 링크를 고칠지"를 알려주는 숨은 칸(<input type="hidden" name="id">)이 있습니다. 이 값은 브라우저 개발자 도구로 누구나 바꿀 수 있어요. 서버가 id = 4만 보고 수정하면, 남의 4번 링크를 바꿀 수 있게 됩니다.

그래서 조건을 "id가 4 그리고 주인이 요청한 사람"으로 겁니다. 남의 링크 id를 보내면 조건에 맞는 줄이 0개라 아무것도 바뀌지 않습니다.

app/actions/links.js를 아래로 바꿉니다. 맨 아래에 updateLink, deleteLink가 추가되었고, 맨 위 import에 and가 추가되었습니다.

링크 한 줄을 보여주는 부품을 만듭니다. "수정"을 누르면 그 자리에서 입력 폼으로 바뀝니다.

📖 용어 풀이useState: 화면이 기억하는 값(상태)입니다. editing이 true면 수정 폼을, false면 보기 화면을 그립니다. setEditing(true)로 값을 바꾸면 React가 화면을 알아서 다시 그립니다.

대시보드 목록이 이 부품을 쓰도록 바꿉니다.

✅ 여기까지 됐는지 확인하는 법
  1. 수정 → 주소를 not a url로 바꿔 저장 → 에러가 보이고 입력한 값이 남아 있다
  2. 수정 → 제목·주소를 올바르게 바꿔 저장 → 보기 화면으로 돌아오며 바뀐 내용이 보인다
  3. 삭제 → 목록에서 사라지고, 개수가 줄면 추가 폼이 다시 나타난다
  4. 두 탭 실험: 링크가 2개인 상태에서 대시보드를 탭 2개로 연다. 탭 A에서 1개 추가(3개가 됨). 탭 B에는 아직 폼이 보이는데, 여기서 추가하면 → "무료 버전은 링크를 3개까지만 만들 수 있어요." 화면(탭 B)은 속았지만 서버가 막은 것입니다.
🧪 도전: 남의 링크 수정해보기 (해킹 흉내)
  1. 시크릿 창에서 다른 계정으로 가입하고 링크 1개를 만든다
  2. Neon → Tables → link에서 그 링크의 id를 확인한다 (예: 4)
  3. 원래 창의 대시보드에서 "수정"을 누르고, F12 → Elements 탭에서 input type="hidden" name="id"의 value를 그 번호로 바꾼 뒤 저장
  4. → "링크를 찾을 수 없습니다." Neon에서 다른 계정의 링크가 그대로인지 확인

3공개 페이지 만들기 (/사용자이름)

누구나 볼 수 있는 페이지입니다. 주소가 사람마다 다르므로 동적 주소를 씁니다.

📖 용어 풀이동적 주소(Dynamic Route): 폴더 이름을 대괄호로 감싸면(app/[username]) 그 자리에 어떤 값이 와도 이 페이지가 열립니다. /andrew로 접속하면 코드 안에서 username이 "andrew"가 됩니다. /login처럼 이미 있는 폴더가 우선이라 겹치지 않습니다.

폴더 이름을 대괄호까지 포함해 [username]으로 만들고, 그 안에 page.js를 만듭니다.

💡 여기는 왜 로그인 확인이 없나요?공개 페이지는 읽기만 하는 곳이라 누구나 봐도 됩니다. 대신 DB에서 가져오는 칸을 id, username, displayUsername과 title, url로 딱 필요한 것만 골랐습니다. 이메일 같은 개인정보가 공개 페이지로 새어 나가지 않게 하려는 것입니다.

없는 사용자 주소로 들어왔을 때 보여줄 페이지도 한국어로 만듭니다. app 폴더 바로 아래에 만드세요.

app/globals.css 맨 아래에 공개 페이지 스타일을 추가합니다.

✅ 여기까지 됐는지 확인하는 법
  • 대시보드의 "공개 페이지: /내이름" 링크 → 둥근 버튼 모양으로 내 링크들이 보인다. 누르면 새 탭으로 열린다
  • 시크릿 창(로그인 안 한 상태)에서도 같은 주소가 보인다
  • 대문자로 /Tester_One처럼 쳐도 같은 페이지가 나온다
  • /nobody_here처럼 없는 이름 → "페이지를 찾을 수 없어요"
  • 대시보드에서 링크를 수정한 뒤 공개 페이지를 새로고침하면 바뀐 내용이 보인다

🆘 3주차에 자주 막히는 곳
링크를 추가했는데 목록에 바로 안 보여요

서버 액션 안에서 revalidatePath("/dashboard")를 호출했는지 확인하세요. refreshPages(user.username)가 빠지면 새로고침해야 보입니다.

Calling setState synchronously within an effect 경고(lint 에러)

수정 성공 후 보기 모드로 돌아가는 코드를 useEffect 안에 넣으면 나오는 경고입니다. 교재 코드처럼 saveLink 함수 안에서 결과를 받은 직후 setEditing(false)를 호출하세요.

공개 페이지가 전부 "찾을 수 없어요"로 나와요

폴더 이름이 정확히 [username](대괄호 포함)인지, findUser에서 await params를 했는지 확인하세요. Next.js 16에서는 params를 await로 꺼내야 합니다.
