모아: 크라우드펀딩 서비스를 만들고, 배포하고, 운영하기

작은 창작자의 프로젝트를 후원하는 서비스(텀블벅 클론)를 실무 순서 그대로 만듭니다. 인터뷰와 기획 → Figma 디자인 → 구현 → 자동 배포 → 운영 → 개선 → 케이스 스터디까지. 1~3단계와 가장 크게 다른 점은 "만들고 끝"이 아니라 "돌아가게 지키는 법"까지 배운다는 것입니다.

이 교재를 읽는 법

4단계는 새로 나오는 개념이 많습니다. 작성자(첫 검증 독자)도 16주차까지 따라 한 뒤 "시키는 대로 따라 했지만, 이해하고 한 것은 아니었다"고 돌아봤습니다. 그래서 모든 단계를 같은 순서로 씁니다.

시작하기 전

주차별로 이동하기

파트마다 순서대로 진행하세요. 각 주차의 정답 코드는 projects/04-tumblbug-mvp/ 에, 주차별 git 태그(예: tumblbug-week11-step2)로 남아 있습니다.

 지금 할 차례20주차케이스 스터디와 마무리접근성·키보드, 운영 종료(데이터 삭제), 완료 기준

이 단계를 끝냈다는 기준

  • 프로젝트·리워드 등록 → 목록 → 리워드 선택 → 배송지 → 결제 → 진행률·남은 수량 반영까지 끊김 없이 동작한다
  • 남은 수량보다 많이 팔리지 않는다 (동시 결제 50건 부하 테스트)
  • 모든 PR 에서 CI 가 통과하고, CI 를 통과한 코드만 자동 배포된다 (PR 마다 미리보기 주소와 DB)
  • 같은 앱을 Docker 이미지로 AWS EC2 에서 HTTPS 로 돌리고, 롤백을 연습하고, 실습 뒤 정리했다
  • 에러가 나면 Sentry 알림이 오고, 사이트가 멈추면 가동 감시 알림이 온다
  • 실제 창작자 1명의 프로젝트를 운영하고 개선 전후 지표가 있다 (강의 뒤)
  • 키보드로 조작할 수 있고, Lighthouse 접근성 90점 이상
  • 케이스 스터디로 포트폴리오에 낼 수 있다
