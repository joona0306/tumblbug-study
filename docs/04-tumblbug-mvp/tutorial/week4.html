디자인 시스템, 시안, 클릭 프로토타입

와이어프레임에 옷을 입힙니다. 그런데 화면을 한 장씩 칠하지 않고, 먼저 재료(색·글자·간격 = 토큰)와 부품(버튼·입력칸·카드 = 컴포넌트)을 만든 뒤 그걸로 화면을 조립합니다. 마지막으로 클릭되는 프로토타입을 3명에게 써 보게 하고 고칩니다. 코드는 5주차부터 — 이번 주의 토큰 이름이 그대로 코드의 이름이 됩니다.

🗺️ 이번 주 그림 — 재료 → 부품 → 화면 → 사람에게 시험
① 토큰색·글자·간격·모서리 (Light/Dark)
② 컴포넌트버튼·입력칸·카드 — 상태별로
③ 시안모바일 먼저 + 데스크톱
④ 프로토타입 + 사용성 테스트3명 → 고치기
코드color/primary → var(--color-primary)
용어한 줄 뜻
디자인 토큰색·간격 같은 값에 붙인 이름. 화면은 값(#c8342a) 대신 이름(color/primary)을 쓴다
컴포넌트여러 화면에서 다시 쓰는 부품. 하나를 고치면 쓰인 곳이 모두 바뀐다
상태 (variant)같은 부품의 여러 모습 — 기본·포커스·에러·비활성, 선택됨·품절 …
프로토타입시안의 버튼을 눌렀을 때 다음 화면으로 넘어가게 연결한 것. 코드 없이 흐름을 시험
1토큰: 색·글자·간격·모서리
🗺️ 그림 먼저 — 색은 두 층
원시 색 (Primitives)red/600 = #c8342a, gray/50 …
의미 색 (Color)color/primary · color/bg · color/text …
화면·컴포넌트의미 색만 쓴다

다크 모드는 의미 색이 가리키는 원시 색만 바꿔 끼운다 (color/primary: Light → red/600, Dark → red/300). 화면이 원시 색을 직접 쓰면 다크 모드에서 안 바뀐다.

종류Figma 변수 이름 (예시 파일)코드 (5주차, app/globals.css)
의미 색 22개 (Light/Dark)color/bg · color/surface · color/text · color/text-muted · color/border · color/primary · color/danger …var(--color-bg) · var(--color-primary) …
간격 7단계spacing/xs(4) · sm(8) · md(12) · lg(16) · xl(24) · 2xl(32) · 3xl(48)var(--spacing-lg) …
모서리 4단계radius/sm(6) · md(12) · lg(16) · fullvar(--radius-md) …
글자 9단계 (Noto Sans KR)Display · Heading XL/L/M · Body M · Body M Strong · Body S · Label · Caption.text-display · .text-heading-l · .text-caption …
💡 왜 이름을 코드와 똑같이?디자이너가 "color/primary 를 조금 어둡게" 하면 개발자는 --color-primary 한 곳만 고치면 됩니다. 이름이 다르면 매번 "이 빨강이 그 빨강인가?"를 맞춰 봐야 해요. 정답 코드에는 이름이 같은지 검사하는 테스트(tests/tokens.test.ts)까지 있습니다.
✅ 확인하는 법Figma Local variables 에 Primitives · Color(Light/Dark) · Spacing · Radius 모음이 있고, 글자색과 배경의 대비가 4.5 : 1 이상이다 (Figma 플러그인이나 온라인 대비 검사기로).
🆘 막혔을 때
Figma 변수(Variables)가 어디 있나요?

아무것도 선택하지 않은 상태에서 오른쪽 패널의 Local variables(로컬 변수) → 새 모음(Collection) → 변수 추가. 모드(Mode)를 추가하면 Light/Dark 두 칸이 생깁니다. 메뉴 이름은 Figma 업데이트로 바뀔 수 있어요 — 예시 파일의 Foundations 페이지를 복제해서 시작해도 됩니다.

🔁 방금 무슨 일이 일어났나화면에 쓸 모든 값에 이름을 붙였습니다. 이제 화면은 "빨강"이 아니라 "주요 색(primary)"을 씁니다 — 그래서 다크 모드와 코드 옮기기가 쉬워집니다.
2아이콘과 상태별 컴포넌트
💡 왜 "상태별"로?버튼은 평소·눌렀을 때·비활성·처리 중… 모습이 여럿입니다. 시안에 기본 모습만 있으면 개발할 때 나머지를 즉석에서 지어내게 되고, 화면마다 제각각이 됩니다.
컴포넌트 (예시 파일 19종 중)상태
Button종류(주요·보조…) × 크기 × 상태(기본·호버·비활성…)
Input기본 · 포커스 · 에러(이유 문장) · 비활성
ProgressBar · Badge진행률, D-day 배지
RewardCard기본 · 선택됨 · 품절
LikeButton찜 안 함 · 찜함
Steps · BottomBar · Toast후원 단계 표시, 하단 고정 바, 알림

아이콘은 Lucide(무료, ISC 라이선스) 24개 — 코드에서도 lucide-react 의 같은 이름을 씁니다 (예: Heart, Plus).

입력 규칙 문장은 코드의 검사 문장과 같아야 합니다. 예: 목표 금액 10,000원 ~ 1억 원, 마감일 내일 ~ 60일 뒤, 리워드 가격 1,000원 ~ 1,000,000원 (lib/validation/project.ts, reward.ts).

✅ 확인하는 법Button·Input·RewardCard 의 모든 상태가 컴포넌트 변형(variant)으로 있고, 에러 상태의 문장이 위 규칙과 같다.
🔁 방금 무슨 일이 일어났나화면을 조립할 부품을, 모든 모습까지 포함해 만들었습니다. 5주차에 같은 이름의 React 컴포넌트가 됩니다.
🤔 스스로 확인
RewardCard 에 "품절" 상태가 꼭 있어야 하는 이유는?

PRD 인수 조건(B-3)이 "품절은 선택 불가" 이고, 상태 전이도의 "남음 → 품절" 이 화면에서 보여야 하기 때문입니다. 시안에 없으면 품절 모습을 개발하면서 즉석으로 정하게 됩니다.

3시안 (모바일 먼저 + 데스크톱)

3주차 와이어프레임을 컴포넌트로 조립합니다. 예시 파일 Screens: 모바일 14개 + 데스크톱 3개 + 다크 모드 2개.

  • 화면에는 컴포넌트 인스턴스와 토큰만 — 색 값을 직접 넣지 않는다
  • 로딩·비어 있음·에러 상태 화면도 함께
  • 상태를 어디에 두는지 메모(💡)를 시안 옆에 달아 두면 5주차 상태 관리 지도가 쉬워진다 (예: "필터 = 주소(URL)", "후원 단계 선택 = 브라우저 저장")
✅ 확인하는 법와이어프레임의 세 화면이 모바일·데스크톱 시안으로 있고, 다크 모드로 바꿔도 글자가 잘 보인다.
🆘 막혔을 때
작성자 경험: 첫 시안이 "포트폴리오 수준이 아니다"

교재의 예시 파일도 v1 을 버리고 v2 로 다시 만들었습니다 (Archive — v1 페이지에 개선 전 시안이 남아 있어요). 브랜드(이름·로고)·아이콘·상태별 컴포넌트·데스크톱 화면을 더하면서 좋아졌습니다. 전후 비교는 케이스 스터디의 좋은 재료예요.

🔁 방금 무슨 일이 일어났나재료와 부품으로 실제 화면을 조립했습니다. 부품이 같으니 화면들이 자연스럽게 한 서비스처럼 보입니다.
4클릭 프로토타입과 사용성 테스트 3명
💡 왜 코드 전에 시험하나?코드로 만든 뒤 고치면 몇 시간, 프로토타입에서 고치면 몇 분입니다. 만든 사람은 어디를 눌러야 하는지 알기 때문에 막히는 곳을 보지 못해요 — 다른 사람의 손이 필요합니다.
  1. Figma Prototype 탭에서 버튼마다 다음 화면을 연결: 홈 → 상세 → 후원 1·2·3단계 → 완료
  2. 3명에게 과제 하나만 줍니다: "마음에 드는 프로젝트에 리워드를 골라 후원해 보세요"
  3. 도와주지 않고, 생각을 소리 내어 말해 달라고 부탁한 뒤 관찰만 합니다 — 어디서 멈칫했나, 무엇을 눌렀나
  4. 3명 중 2명 이상이 막힌 곳부터 고칩니다
기록 양식예
어느 화면에서후원 1단계
무엇을 하려다수량을 늘리려고
무엇을 했나 / 말했나 (그대로)"숫자를 눌러도 안 바뀌네요?"
고친 것+/− 버튼을 크게, 숫자 옆에 배치
✅ 확인하는 법3명의 관찰 기록이 있고, 고친 것 1~2개의 전/후 캡처가 있다.
🆘 막혔을 때
참가자가 막히면 알려 줘도 되나요?

1~2분은 기다립니다. 정말 멈추면 "지금 무엇을 찾고 계세요?" 라고만 묻고, 답은 알려 주지 않아요. 막힌 그 순간이 가장 소중한 기록입니다.

🔁 방금 무슨 일이 일어났나코드 한 줄 없이 흐름 전체를 다른 사람의 손으로 시험하고 고쳤습니다. 17~20주차의 "관찰 → 가설 → 개선"을 작게 한 번 해 본 것이에요.
🤔 스스로 확인
참가자에게 "이 버튼 누르시면 돼요"라고 알려 주면 무엇을 잃나?

그 버튼이 찾기 어렵다는 사실을 잃습니다. 실제 사용자 옆에는 알려 줄 사람이 없으니까요.

한 명만 막힌 곳은 어떻게 할까?

바로 고치기보다 기록해 두고 다음 참가자에게서 반복되는지 봅니다. 쉽게 고칠 수 있는 문구 문제라면 같이 고쳐도 됩니다.
