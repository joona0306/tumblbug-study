운영 시작: 남이 쓰는 것을 지켜본다

지금까지는 내가 만들고 내가 써 봤습니다. 이번 주부터는 창작자 1명의 프로젝트를 올리고 지인 3~5명이 테스트 결제로 후원하게 합니다. 내가 예상하지 못한 곳에서 막힐 거예요 — 그게 가장 소중한 정보입니다.

📌 17~20주차는 강의 뒤에 여러분이 직접교재는 이 과정을 [가상] 사례(방문자 42명, 설문 8건)로 끝까지 미리 보여 줍니다. 코드 개선과 측정처럼 실제로 한 것은 [실제]로 따로 표시합니다. 여러분은 같은 순서를 진짜 사용자와 반복합니다.

app/privacy/page.tsx 전체 보기 — 무엇을·왜·누가·어디에·언제까지
💡 개인정보 안내는 코드와 같아야 한다"무엇을 저장하나" 표는 코드가 실제로 저장하는 것과 하나하나 맞췄습니다 (가입 정보, 로그인 기록의 IP·브라우저, 배송지, 방문자 무작위 쿠키, 요청 수 제한용 IP 는 하루 뒤 삭제). 새로 저장하는 값이 생기면 이 화면도 함께 고칩니다. 학습용 안내문이며 법률 검토를 받은 약관은 아닙니다.
✅ 확인하는 법 [실제]모든 화면 위에 노란 띠, 아래에 푸터, /privacy 200 · 흐름 테스트 e2e/launch.spec.ts
🔁 방금 무슨 일이 일어났나처음 오는 사람이 진짜 결제로 오해하지 않게(안내 띠), 무엇을 저장하는지 알 수 있게(개인정보 안내), 막힌 곳을 알려 줄 수 있게(의견 보내기) 했습니다. 실제 사람을 받기 위한 최소한의 예의입니다.
2의견 보내기 — Google 설문지
  1. forms.google.com → 새 설문지. 질문은 짧게 (2분): 역할 · 어디까지 해 봤나 · 가장 헷갈리거나 막혔던 곳(가장 중요) · 좋았던 점 · 기기 · (선택) 연락처
  2. 위쪽 설정 탭 → 응답: 이메일 주소 수집 → 수집하지 않음 · 응답 횟수 1회로 제한 → 끔 (켜면 Google 로그인을 해야 답할 수 있다)
  3. 오른쪽 위 게시 → 응답자: 링크가 있는 모든 사용자 → 응답자 링크 복사 (URL 단축 → https://forms.gle/…)
  4. Vercel → Settings → Environment Variables → NEXT_PUBLIC_FEEDBACK_URL = 그 주소 · Production · 종류 Config
  5. 다시 배포해야 반영됩니다 (아무 PR 이나 합치거나 Deployments → Redeploy)
🆘 작성자가 실제로 막힌 곳
"보내기" 버튼이 없고 "게시"가 있어요

2026-09 화면 기준 Google 설문지는 게시로 공개합니다. 예전 안내의 "보내기 → 링크"와 같은 일이에요.

주소창의 주소를 넣었더니 이상해요

편집 화면의 …/edit 주소는 편집용입니다. 반드시 응답자 링크를 넣으세요. 시크릿 창(Ctrl+Shift+N)에서 로그인 없이 열리면 맞습니다.

넣었는데 화면에 링크가 안 보여요

Type 을 Secret 으로 넣으면 GitHub Actions 빌드 때 값이 오지 않습니다 (14주차). NEXT_PUBLIC_ 값은 빌드할 때 화면 코드에 새겨지므로 Config 로 넣고 다시 배포합니다.

🔁 방금 무슨 일이 일어났나로그인·이메일 없이 답할 수 있는 설문지를 만들고, 그 주소를 Vercel 에 Config 종류로 넣었습니다. NEXT_PUBLIC_ 값은 빌드 때 화면 코드에 새겨지므로 다시 배포해야 링크가 나타납니다.

초대하기

운영 주소를 QR 코드로 (Chrome 주소창 → 공유 → QR 코드 만들기). 소개할 때 말할 것: ① 교재로 만든 학습용 서비스 ② 결제는 테스트, 청구 없음 ③ 배송지는 가짜 주소도 된다, 스터디가 끝나면 모두 지운다 ④ 막힌 곳이 가장 소중한 정보 — "의견 보내기"로. 창작자·후원자에게 보낼 안내문은 projects/04-tumblbug-mvp/docs/launch.md 4·5번에 있습니다.

💡 사용자가 막혔다고 하면그 자리에서 고쳐 주지 말고 먼저 적습니다 — 어느 화면에서, 무엇을 하려다, 무엇을 봤나. 한 명이 막힌 곳은 다른 사람도 막힙니다.
