인증과 프로젝트 등록

로그인을 붙이고, 로그인한 창작자가 자기 프로젝트를 만들고 고칠 수 있게 합니다. 핵심은 "화면이 막는 것은 편의, 서버가 막는 것이 보안"입니다.

🗺️ 이번 주 그림 — "누가" 요청했나를 알게 된다
가입·로그인Better Auth → 쿠키
proxy.ts로그인 필요한 주소 앞문
requireUser()진짜 확인 · 내 것만
프로젝트 등록zod + 사진 + DB
용어한 줄 뜻
세션·쿠키로그인한 상태를 기억하는 표(DB)와, 브라우저가 들고 다니는 증표
서버 액션폼을 제출하면 서버에서 도는 함수 ("use server")
proxy페이지를 그리기 전에 요청을 먼저 받는 문지기 (Next.js 16, 예전 middleware)
오픈 리다이렉트로그인 뒤 돌아갈 주소에 바깥 사이트를 넣어 사용자를 속이는 공격
1회원가입 · 로그인 · 로그아웃
🗺️ 그림 먼저 — 로그인은 "쿠키"를 받는 일
로그인 폼이메일·비밀번호
zod 검사칸마다 이유
Better Auth비밀번호 확인 → 세션 저장(DB)
브라우저 쿠키다음 요청부터 "나"를 증명

인증 설정은 6주차에 표를 만들면서 이미 두었습니다. 사용자 이름(username) 칸과 역할(role — 가입할 때 스스로 정할 수 없음)이 들어 있어요.

💡 로그인 뒤 "원래 보던 곳"으로 보낼 때 왜 주소를 검사하나요?/login?redirect=https://나쁜사이트.com 처럼 바깥 주소를 넣어 두면, 로그인한 사용자를 가짜 사이트로 보낼 수 있습니다(오픈 리다이렉트). 우리 사이트 안의 경로(/ 로 시작)만 허용하고, //evil.com 처럼 속이는 주소도 막습니다.
✅ 확인하는 법
  • /signup 에서 가입 → 자동으로 로그인되어 상단에 내 이름
  • 로그아웃 → 로그인 버튼
  • 틀린 비밀번호 → "이메일 또는 비밀번호가 틀렸어요."
🆘 막혔을 때
가입이 "이미 가입된 이메일"로 막혀요

시드(npm run db:seed)가 만든 예시 계정 이메일과 겹쳤을 수 있습니다. 다른 이메일로 가입하거나 예시 계정(…@seed.moa.test / moa-dev-1234)으로 로그인하세요.

🔁 방금 무슨 일이 일어났나가입·로그인이 되면 서버가 세션을 DB 에 저장하고 브라우저에 쿠키를 줍니다. 앞으로 "누가 요청했나"는 이 쿠키로 서버가 판단합니다.
🤔 스스로 확인
비밀번호가 틀렸을 때 폼에 비밀번호를 다시 채워 주지 않는 이유는?

비밀번호를 응답에 담아 보내면 화면·기록 어딘가에 남을 수 있습니다. 이메일만 다시 채우고 비밀번호는 다시 입력하게 합니다.

2proxy.ts 로 로그인이 필요한 주소 막기
🗺️ 그림 먼저 — 문지기는 두 명
proxy.ts (앞문)쿠키가 "있는지"만 · 빠름 · DB 안 봄
requireUser() (안쪽)쿠키가 "진짜인지" · DB 로 확인

proxy 는 편의(로그인 화면으로 빨리 보내기), requireUser 는 보안(진짜 확인). 쿠키가 있어도 만료·위조일 수 있다.

📌 Next.js 16 에서 바뀐 것예전 middleware.ts 가 proxy.ts 로 이름이 바뀌었습니다 (함수 이름도 proxy). 인터넷의 옛 글은 middleware 라고 되어 있을 수 있어요.
💡 관리자가 아닌 사람에게 403(권한 없음) 대신 404(없음)를 보여 주는 이유는?403 은 "여기에 관리자 화면이 있다"는 사실을 알려 줍니다. 404 로 보여 주면 존재 자체를 숨길 수 있어요. (Next.js 의 forbidden() 은 아직 실험 기능이라 notFound() 를 씁니다)
✅ 확인하는 법로그아웃 상태로 /projects/new → /login?redirect=%2Fprojects%2Fnew 로 가고, 로그인하면 /projects/new 로 돌아온다
🔁 방금 무슨 일이 일어났나로그인이 필요한 주소를 앞문에서 빠르게 걸러 내고, 진짜 확인은 페이지·서버 액션 안에서 한 번 더 합니다.
🤔 스스로 확인
proxy 만 믿고 requireUser 를 빼면 무엇이 위험할까?

쿠키 이름만 흉내 낸 가짜 쿠키나 만료된 쿠키로도 들어올 수 있습니다. proxy 는 쿠키가 있는지만 보기 때문입니다.

3프로젝트 만들기·수정 (zod 검사 + 사진 업로드)
🗺️ 그림 먼저 — 사진은 브라우저에서 줄여서 보낸다
휴대폰 사진3~10MB
1280px JPEG0.2~0.5MB
서버: 검사로그인? 칸마다 zod? 사진 형식·크기?
Vercel Blob사진 파일
DB프로젝트 + 사진 주소

3단계 당근마켓의 사진 업로드와 같은 흐름. 차이: 목표 금액·마감일처럼 규칙이 더 많다.

💡 zod 규칙(목표 1만~1억)과 DB CHECK 가 같은 이유는?화면에서 먼저 친절하게(칸 아래 한국어 문장) 알려 주고, DB 는 마지막 방어선입니다. 둘이 다르면 "화면은 통과했는데 저장이 안 되는" 이상한 일이 생겨요.
✅ 확인하는 법
  • 빈 칸으로 제출 → 칸마다 이유 (제목·카테고리·사진)
  • 사진을 골라 만들기 → 수정 화면으로 이동, 사진이 Blob 에 올라감
  • 남의 프로젝트 수정 주소 → 404
🆘 막혔을 때
사진을 올리면 "Body exceeded 1 MB limit"

서버 액션의 기본 요청 크기는 1MB 입니다. next.config.ts 의 bodySizeLimit: "2mb" 와, 브라우저에서 줄이는 resizeImage 가 둘 다 있는지 확인하세요.

사진이 화면에 안 나와요 (Invalid src)

next.config.ts 의 images.remotePatterns 에 Blob 주소가 있어야 <Image> 가 보여 줍니다.

🔁 방금 무슨 일이 일어났나창작자가 프로젝트를 만들 수 있게 됐습니다. 브라우저 → 서버 검사 → 사진 저장소 → DB 순서로 값이 흐르고, 검사는 서버에서 반드시 한 번 더 합니다.
🤔 스스로 확인
후원이 들어온 뒤에는 목표 금액·마감일을 못 바꾸게 한 이유는?

후원자는 그 목표와 마감을 보고 후원했습니다. 나중에 바꾸면 약속이 달라지므로, 결제 완료 후원이 있으면 두 칸을 잠급니다 (hasPaidFunding).
