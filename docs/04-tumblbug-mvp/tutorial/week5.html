1프로젝트 만들기 + Figma 토큰을 CSS 변수로
🗺️ 그림 먼저 — Figma 와 코드가 같은 이름을 쓴다
Figma 변수color/primary, spacing/lg
design/figma-tokens.json값을 글자로 저장
app/globals.css--color-primary, --spacing-lg
tests/tokens.test.ts둘이 다르면 CI 실패

디자이너(Figma)와 개발자(코드)가 같은 단어로 말하게 한다. 한쪽만 바꾸면 테스트가 알려 준다 (이번 주 3단계에서 만든다).

1~3단계처럼 Next.js 프로젝트를 새로 만듭니다. 이번에는 처음부터 TypeScript(--ts)로 — 3단계 1주차에 손으로 바꾼 것을 도구가 대신 해 줍니다. 정답 코드 폴더 이름은 04-tumblbug-mvp, 여러분의 폴더는 my-moa 로 합니다.

4주차 Figma 에서 만든 색·간격 변수를 그대로 옮깁니다. 먼저 값을 파일로 내보내고, 같은 이름의 CSS 변수를 만듭니다.

💡 왜 색이 두 층(원시 색 → 의미 색)인가요?화면 코드는 var(--color-primary) 처럼 의미로만 씁니다. 다크 모드가 되면 의미 색이 가리키는 원시 색만 바뀌어요. 화면 코드에서 --red-600 을 직접 쓰면 다크 모드에서 안 바뀌는 곳이 생깁니다.
✅ 확인하는 법
  • npm run dev → http://localhost:3000 이 뜬다
  • 브라우저 개발자 도구 → Elements → :root 에 --color-primary 가 보인다
🔁 방금 무슨 일이 일어났나Figma 의 이름(color/primary)이 코드의 이름(--color-primary)이 되었습니다. 이제 "그 버튼 색"을 말할 때 디자인과 코드가 같은 단어를 씁니다.
🤔 스스로 확인
화면 코드에서 원시 색(--red-600)을 직접 쓰면 무엇이 곤란할까?

다크 모드에서 의미 색만 바뀌기 때문에, 원시 색을 직접 쓴 곳은 라이트 모드 색 그대로 남습니다.

2디자인 시스템 컴포넌트 (Button · Badge · ProgressBar · Chip · Field)
🗺️ 그림 먼저 — Figma 컴포넌트 = React 컴포넌트
Figma ButtonVariant × Size × State
components/ui/Button.tsxvariant · size · icon
CSS 변수(토큰)만숫자·색을 직접 적지 않는다
💡 왜 링크 모양 버튼(ButtonLink)을 따로 만드나요?이동은 링크(<a>), 동작은 버튼(<button>). 겉모양이 같아도 화면 낭독기는 둘을 다르게 읽고, 키보드 동작도 다릅니다 (링크는 Enter, 버튼은 Enter·Space). 모양만 보고 고르지 않습니다.

같은 방법으로 Badge(모금중·성공·실패·D-3), ProgressBar(달성률 — 132% 여도 막대는 100에서 멈추고 읽어 주는 글자는 132%), Chip(카테고리 선택 = 주소가 바뀌는 링크), Field(이름표 + 칸 + 에러 문장)를 만들고, 한 화면(/design-system)에 모아 봅니다.

✅ 확인하는 법
  • http://localhost:3000/design-system 에 버튼(보통·비활성), 배지, 진행률 3개, 칩, 입력칸(보통·에러)이 보인다
  • Tab 키로 이동하면 파란 초점 테두리가 보인다
🆘 막혔을 때
아이콘이 안 보여요

lucide-react 가 설치됐는지(npm i lucide-react@1.48.0), 아이콘 이름이 Figma Icons 페이지의 이름과 같은지 확인하세요.

🔁 방금 무슨 일이 일어났나Figma 에서 만든 부품을 코드 부품으로 옮겼습니다. 앞으로 화면을 만들 때는 이 부품만 조립합니다 — 색과 간격을 다시 고민하지 않아도 돼요.
🤔 스스로 확인
ProgressBar 가 132% 일 때 막대와 읽어 주는 글자를 다르게 하는 이유는?

막대는 화면을 넘칠 수 없으니 100에서 멈추지만, 실제 달성률(132%)은 정확히 알려야 하기 때문입니다 (aria-valuenow=100, aria-valuetext=132%).

3zod 로 환경 변수 검사 + Vitest 단위 테스트
🗺️ 그림 먼저 — 틀린 설정을 "켜는 순간" 잡는다
.env.local사람이 손으로 적는 값
lib/env.ts (zod)모양 검사
시작할 때 멈춤무엇이 틀렸는지 문장으로

검사가 없으면 앱은 켜지고, 한참 뒤 엉뚱한 화면에서 이상하게 동작한다 — 원인을 찾기 어렵다.

zod = 값의 "모양"을 선언하고 검사하는 도구. Vitest = 함수 하나하나가 맞게 동작하는지 빠르게 확인하는 단위 테스트 도구.

1단계에서 말한 "디자인 = 코드" 약속도 테스트로 지킵니다:

💡 왜 process.env 를 직접 읽지 않고 인자로 받나요?parseEnv(values) 처럼 값을 인자로 받으면 테스트에서 아무 값이나 넣어 볼 수 있습니다. 함수가 바깥(환경 변수)을 몰래 읽으면 테스트하기 어려워요 — 8주차 "순수 함수"에서 다시 만납니다.
✅ 확인하는 법
  • npm test → env·format·tokens 테스트 모두 통과
  • globals.css 의 --color-primary 값을 하나 바꾸고 npm test → 토큰 테스트가 실패하는지 (확인 뒤 되돌리기)
🆘 막혔을 때
Vitest 가 @types/node 버전 경고를 내요

Vitest 5 는 Node 22 타입을 요구합니다. @types/node@22 로 고정하세요.

🔁 방금 무슨 일이 일어났나설정이 틀리면 앱이 "켜지지 않고 이유를 말하게" 했고, 디자인과 코드가 어긋나면 테스트가 실패하게 했습니다. 사람이 기억하지 않아도 도구가 지켜 줍니다.
🤔 스스로 확인
일부러 토큰 값을 바꿔 테스트를 실패시켜 보는 이유는?

테스트가 정말 그 실수를 잡는지 확인하기 위해서입니다. 한 번도 실패해 본 적 없는 테스트는 아무것도 지키지 못할 수도 있어요.

4Playwright 흐름 테스트 (휴대폰·데스크톱)
🗺️ 그림 먼저 — 단위 테스트와 흐름 테스트
Vitest (단위)함수 하나 · 수 ms · 화면 없음
Playwright (흐름)진짜 브라우저로 사람처럼 누른다 · 수 초

둘 다 필요하다: 규칙(계산)은 단위 테스트로 촘촘히, 사람이 겪는 흐름은 흐름 테스트로 굵게.

💡 왜 getByRole(역할)로 찾나요?"버튼 중에 이름이 '후원하기'인 것"처럼 화면 낭독기가 찾는 방식과 같습니다. 그래서 테스트가 통과하면 접근성도 어느 정도 확인됩니다. CSS 클래스로 찾으면 디자인만 바꿔도 테스트가 깨져요.
✅ 확인하는 법npm run test:e2e → mobile·desktop 두 기기로 모두 통과
🔁 방금 무슨 일이 일어났나진짜 브라우저가 휴대폰 크기와 데스크톱 크기로 앱을 열어 보고, 사람이 보는 것(역할·이름)으로 확인했습니다.
5GitHub Actions CI + PR 템플릿
🗺️ 그림 먼저 — PR 을 열면 GitHub 이 대신 검사한다
PR 열기브랜치에서 main 으로
CI코드 검사 → 타입 → 단위 → 빌드 → 흐름
빨간 X합치기 전에 고친다
💡 왜 합치기 전에 검사하나요?main 은 "언제든 배포해도 되는 코드"여야 합니다(14주차에 자동 배포). 사람이 매번 기억해서 검사하면 빠뜨리는 날이 생겨요. PR 템플릿은 스스로 점검할 목록 — 코드 리뷰어가 없는 1인 프로젝트에서 특히 중요합니다.
✅ 확인하는 법
  • 브랜치 → 커밋 → push → PR 을 열면 Checks 탭에서 CI 가 돈다
  • 모두 초록이면 합치기
🆘 막혔을 때
npm ci 가 lockfile 오류로 멈춰요

package.json 을 바꾸고 npm install 을 안 해서 package-lock.json 이 옛날 그대로인 경우입니다. 내 컴퓨터에서 npm install 후 lockfile 까지 커밋하세요.

🔁 방금 무슨 일이 일어났나이제 모든 코드는 "GitHub 이 검사한 뒤에야" main 에 들어갑니다. 1인 프로젝트에서도 실무와 같은 흐름(브랜치 → PR → CI → 합치기)을 씁니다.
6Sentry 에러 모니터링
🗺️ 그림 먼저 — 사용자가 알려 주기 전에 내가 안다
브라우저·서버에서 에러사용자는 흰 화면
Sentry어느 파일 몇 줄, 몇 명
알림 메일내가 먼저 안다
📌 Sentry 11 에서 바뀐 것withSentryConfig 는 @sentry/nextjs/config 에서 가져오고, 개인정보는 dataCollection 으로 끕니다 (예전 sendDefaultPii 는 없어졌어요). 인터넷의 옛 글과 다를 수 있습니다.
⚠️ 작성자가 실제로 한 실수.env.example 에 진짜 DSN·토큰을 적었다가 커밋 직전에 발견했습니다. .env.example 은 git 에 올라가는 "빈 양식"이고, 진짜 값은 .env.local(git 에 안 올라감)에만 적습니다. 커밋 전에 git diff 로 한 번 더 보세요.
💡 왜 개인정보 수집을 하나씩 끄나요?11주차부터 배송지(이름·연락처·주소)를 다룹니다. 에러와 함께 이런 값이 외부 서비스로 가면 안 됩니다. Sentry 11 은 기본값이 "대부분 수집"이라 직접 끕니다.
✅ 확인하는 법
  • Sentry 에서 프로젝트를 만들고 DSN 을 .env.local 에
  • http://localhost:3000/debug/sentry 에서 버튼으로 에러 → 1~2분 뒤 Sentry Issues 에 보인다
🔁 방금 무슨 일이 일어났나에러가 나면 Sentry 에 모입니다. 아직 "모으기만" 하고, 알림은 15주차에 켭니다.
🤔 스스로 확인
.env.example 과 .env.local 의 차이는?

.env.example 은 git 에 올라가는 빈 양식(어떤 값이 필요한지 알려 주는 용도), .env.local 은 git 에 올라가지 않는 진짜 값입니다.

🗺️ 그림 먼저 — 질문을 위에서부터 차례로
서버에 저장?→ 서버 상태 (DB)
주소 공유·뒤로가기?→ URL 상태
폼 결과?→ 폼 상태
여러 화면이 함께?→ Zustand
한 컴포넌트만→ useState
💡 왜 코드를 쓰기 전에 표부터?"새로고침하면 왜 선택이 사라지지?", "다른 화면에서는 왜 옛 값이지?" 같은 버그는 대부분 값을 잘못된 곳에 둬서 생깁니다. 표로 먼저 정하면 설계 단계에서 막을 수 있어요. 10주차(Zustand)·12주차(TanStack Query)에 이 표로 돌아옵니다.
🔁 방금 무슨 일이 일어났나앱의 모든 "바뀌는 값"에 집 주소를 정했습니다. 새 기능을 만들 때마다 이 표에 한 줄씩 추가합니다.
🤔 스스로 확인
목록의 카테고리 필터를 useState 에 두면 무엇이 곤란할까?

새로고침·주소 공유·뒤로가기를 하면 사라집니다. 그래서 URL(?category=)에 둡니다.

8첫 CI 실패 고치기 — 글꼴을 npm 패키지로

작성자의 첫 CI 는 빌드에서 실패했습니다. next/font/google 이 한국어 글꼴(Noto Sans KR)의 조각 파일 100개 이상을 빌드 중에 내려받다가 가끔 실패했기 때문이에요.

💡 왜 이게 해결책인가요?글꼴 파일을 npm 패키지로 설치하면 우리 서버가 함께 보내 줍니다. 빌드할 때 인터넷(구글 서버)에 기대지 않으니 CI 가 안정적입니다. "가끔 실패하는 테스트"는 무시하지 말고 원인을 없애야 해요 — 아니면 진짜 실패를 놓칩니다.
✅ 확인하는 법PR 의 CI 가 다시 돌아 초록
🔁 방금 무슨 일이 일어났나CI 가 "내 컴퓨터에서는 되는데" 문제를 찾아 줬습니다. CI 는 늘 깨끗한 컴퓨터에서 처음부터 돌리기 때문에 이런 숨은 의존성이 드러납니다.
