사용자 흐름도, 와이어프레임, 화면-데이터 매핑

PRD 의 사용자 스토리를 화면의 순서로 바꿉니다. 색과 모양은 아직 신경 쓰지 않고(저해상도), 무엇이 어디에 있어야 하는지만 정합니다. 마지막으로 화면에 보이는 글자·숫자 하나하나가 어느 데이터에서 오는지 표로 확인합니다 — 여기서 빠진 데이터를 찾는 것이 이번 주의 가장 큰 수확입니다.

🗺️ 이번 주 그림 — 이야기 → 순서 → 뼈대 → 데이터 확인

1사용자 흐름도 (창작자·후원자·관리자)
💡 왜 화면보다 흐름을 먼저?화면을 한 장씩 그리면 "그다음엔 어디로 가지?", "로그인 안 했으면?"을 놓칩니다. 흐름도는 갈림길을 먼저 드러내요. 갈림길마다 화면이나 안내 문구가 하나씩 필요합니다.
🗺️ 후원자 흐름 (여러 단계 후원 포함)
홈 / 목록카드: 사진·진행률·남은 일수
상세로그인했나? → 아니면 로그인 후 돌아오기
① 리워드품절은 선택 불가 · 리워드 없이도 가능
② 배송지배송이 없으면 건너뜀
③ 확인·결제토스 결제창
성공 / 실패→ 내 후원 내역
  • 창작자: 가입 → 프로젝트 올리기(기본 정보·사진) → 리워드 추가 → 스튜디오에서 모금 현황·후원자·배송지
  • 관리자: 관리자 화면 → 프로젝트 숨기기 · 결제 실패 목록
  • 갈림길 예: 로그인 여부, 내 프로젝트인가(내 프로젝트에는 후원 불가), 품절인가, 마감이 지났나, 배송이 필요한 리워드인가

예시: Figma 예시 파일(크라우드펀딩 MVP — 예시 v2)의 Flow 페이지

✅ 확인하는 법세 역할의 흐름이 있고, 갈림길 5개 이상에 "예/아니오" 화살표가 모두 있다.
🆘 막혔을 때
Figma 가 처음이에요

새 디자인 파일 → 왼쪽 위 도구에서 사각형(R)·글자(T)·화살표(Shift+L)만 써도 흐름도는 충분합니다. FigJam(Figma 의 화이트보드)이나 종이에 그려서 사진을 찍어도 괜찮아요 — 이번 주는 도구보다 갈림길이 중요합니다.

🔁 방금 무슨 일이 일어났나사용자 스토리를 "화면의 순서와 갈림길"로 바꿨습니다. 갈림길 하나하나가 나중에 코드의 if 와 테스트가 됩니다.
🤔 스스로 확인
배송이 필요 없는 리워드를 고르면 흐름이 어떻게 달라지나?

② 배송지 단계를 건너뛰고 바로 ③ 확인·결제로 갑니다. 이 갈림길은 15·18주차 퍼널 분석에서 "결제 요청 비율이 부풀려지는" 원인이 되기도 해요.

2와이어프레임 (저해상도)
💡 왜 회색 상자부터?색과 글꼴이 들어가면 "예쁜가"에 눈이 가서 "필요한 게 다 있나"를 놓칩니다. 회색 상자는 고치는 데 1분이라 마음껏 바꿔 볼 수 있어요.

최소 세 장: 홈 · 상세 · 후원 1단계 (예시 파일의 Wireframes 페이지). 모바일 먼저(가로 390px 정도) 그립니다 — 좁은 화면에서 되면 넓은 화면은 쉽습니다.

화면꼭 있어야 할 것 (PRD 인수 조건에서)
홈·목록 카드사진 · 제목 · 진행률 막대 · % · 남은 일수 · 찜 하트
상세창작자 · 목표·모인 금액 · 후원자 수 · 마감일 · 리워드 목록(남은 수량) · 하단 고정 "후원하기"
후원 1단계단계 표시(① ② ③) · 리워드 선택(품절 표시) · 수량 · 추가 후원금 · 총액 · 다음
🆘 잊기 쉬운 화면 상태

화면마다 로딩 중 · 비어 있음 · 에러 모습도 한 칸씩 그려 두세요. 예: 찜한 프로젝트가 없을 때 "아직 찜한 프로젝트가 없어요 + 둘러보기 버튼". 13주차에 이 그림대로 만듭니다.

✅ 확인하는 법세 장의 와이어프레임에 위 표의 요소가 모두 있고, 비어 있음/에러 상태가 최소 1개씩 있다.
🔁 방금 무슨 일이 일어났나"무엇을 어디에"를 정했습니다. 다음 주 디자인 시스템은 이 뼈대에 옷을 입히는 일입니다.
3화면-데이터 매핑표 — 빠진 데이터 찾기
💡 왜?시안에 "찜 → 후원 전환율 4.0%" 를 그려 놓고 개발을 시작했는데, 그걸 계산할 데이터가 없다면? 이 표는 개발을 시작하기 전에 그런 구멍을 찾아 줍니다.

와이어프레임의 글자·숫자 하나하나에 대해 "어느 개체의 어느 속성에서, 어떻게 계산되어, 누가 볼 수 있나"를 적습니다. 예시: templates/07-data-model.md ②

화면보이는 것출처계산누가 볼 수 있나
목록 카드진행률 78%후원(결제 완료)의 총액 합계 ÷ 목표 금액합계모두
목록 카드12일 남음마감일 − 오늘계산모두
상세12개 남음리워드 수량 한정 − 판매 수량계산모두
대시보드최근 후원자·배송지후원의 배송지 속성목록그 프로젝트 창작자만, 결제 완료 건만
✅ 확인하는 법와이어프레임의 모든 숫자가 표에 있고, "출처" 칸이 빈 줄이 없다. 비어 있던 줄은 ERD 를 고쳤거나 시안에서 뺐다.
🆘 막혔을 때
출처를 모르겠는 숫자가 있어요

그게 바로 이 표가 찾아 준 구멍입니다. 개념 ERD 에 속성을 더하거나(예: 찜에 날짜), 그 숫자를 시안에서 빼세요. 둘 중 무엇을 골랐는지 한 줄 남기면 좋은 ADR 재료가 됩니다.

🔁 방금 무슨 일이 일어났나화면(디자인)과 데이터(ERD)를 한 줄씩 맞춰 봤습니다. "누가 볼 수 있나" 칸은 7주차 권한 설계로 이어집니다.
🤔 스스로 확인
진행률을 프로젝트 표에 저장해 두지 않고 매번 계산하는 이유는?

저장하면 후원이 들어올 때마다 두 곳을 고쳐야 하고, 하나라도 빠지면 값이 어긋납니다. "같은 사실은 한 곳에만" (정규화) — 6주차에 자세히 봅니다.

매핑표의 "누가 볼 수 있나" 칸은 왜 필요할까?

배송지 같은 개인정보는 정해진 사람만 봐야 합니다. 화면을 설계할 때 정해 두지 않으면, 개발할 때 권한 검사를 빠뜨리기 쉽습니다.
