# PRD (제품 요구사항 문서) — 텀블벅 MVP 예시 답안 (2주차)

> **PRD**: "무엇을, 누구를 위해, 왜 만들고, 어디까지 만들며, 무엇을 보면 성공인지"를 한 문서에 적은 것.
> 개발 중에 "이거 해야 해?"라는 질문이 생기면 이 문서를 보고 답합니다.
>
> 아래는 이 교재의 예시 답안입니다. 여러분은 **자기 인터뷰 결과**를 근거로 고쳐 쓰세요.
> 특히 "근거" 칸은 내 인터뷰 인용으로 채워야 합니다.

## 1. 문제
창작자는 만들고 싶은 것이 있어도 **제작비를 미리 모으기 어렵고**, 후원자는 **믿을 만한 프로젝트인지 판단할 정보**가 부족하다.
- 근거 (예시): "너무 높게 잡았다가 실패할까 봐 낮췄어요." / "0%면 괜히 망설여져요." — *내 인터뷰 인용으로 바꿀 것*

## 2. 대상 사용자
| 사용자 | 설명 | 이 서비스에서 원하는 것 |
|---|---|---|
| 창작자 | 굿즈·책·공연 등을 소규모로 만드는 개인 | 제작비를 모으고, 모금 현황을 쉽게 확인 |
| 후원자 | 좋아하는 창작을 응원하고 싶은 사람 | 믿을 만한 프로젝트를 찾고, 쉽게 후원하고, 결과를 확인 |
| 관리자 | 서비스 운영자 (나) | 문제 있는 프로젝트를 숨기고, 결제 실패를 살핌 |

## 3. 목표 / 비목표
**목표**
- 창작자가 10분 안에 프로젝트를 올릴 수 있다
- 후원자가 상세 페이지에서 리워드 선택 → 배송지 → 결제 3단계로 후원을 끝낼 수 있다
- 수량 한정 리워드가 남은 수량보다 많이 팔리지 않는다
- 마감일에 성공/실패가 자동으로 결정된다

**비목표 (이번에는 안 한다)**
- 리워드 옵션(색상·사이즈), 정산, 환불, 알림, 업데이트 글·댓글, 검색·추천, 실제 결제
- 이유: 20주 안에 **핵심 흐름(등록 → 후원 → 결과)을 운영 수준으로** 완성하는 것이 우선

## 4. 사용자 스토리와 인수 조건
> 형식: "[누구]로서 [무엇]을 하고 싶다, [왜]". 인수 조건 = "이게 되면 이 스토리는 끝"

### 후원자 (B)
| ID | 스토리 | 인수 조건 |
|---|---|---|
| B-1 | 후원자로서 **될 것 같은 프로젝트**를 빨리 찾고 싶다 | 목록 카드에 사진·제목·진행률 막대·%·남은 일수가 보인다. 모금중/성공/실패 필터, 마감 임박순 정렬 |
| B-2 | 후원자로서 프로젝트를 믿을 수 있는지 판단하고 싶다 | 상세에 창작자, 소개, 목표·모인 금액, 후원자 수, 마감일이 있다 |
| B-3 | 후원자로서 **마음에 드는 리워드**를 골라 후원하고 싶다 | 리워드 선택(남은 수량 표시, 품절은 선택 불가) + 수량 + 추가 후원금 → 배송지 → 확인·결제. 단계를 오가거나 새로고침해도 선택 유지. 리워드 없이 1,000원~1,000,000원 후원도 가능. 마감·숨김·내 프로젝트는 서버가 거절 |
| B-4 | 후원자로서 **내가 후원한 프로젝트의 결과**를 알고 싶다 | "내 후원 내역"에 리워드·금액·날짜·배송지·프로젝트 상태(모금중/성공/실패) |
| B-5 | 후원자로서 **나중에 후원할 프로젝트를 모아 두고** 싶다 | 카드·상세의 하트로 찜, 누르자마자 카드·상세·헤더 개수에 반영(실패하면 되돌림), "내 찜" 목록 |

### 창작자 (C)
| ID | 스토리 | 인수 조건 |
|---|---|---|
| C-1 | 창작자로서 프로젝트를 쉽게 올리고 싶다 | 대표 사진·제목·한 줄 요약·소개·카테고리·목표 금액·마감일 입력, 잘못된 값은 칸 옆에 이유 표시 |
| C-2 | 창작자로서 모금 전 내용을 고치고 싶다 | 본인 프로젝트만 수정 가능. 후원이 1건이라도 있으면 목표 금액·마감일은 수정 불가 |
| C-3 | 창작자로서 **모금 현황을 한눈에** 보고 싶다 | 대시보드에 프로젝트별 모인 금액·진행률·후원자 수·남은 일수, 리워드별 판매 수량 |
| C-4 | 창작자로서 **리워드를 구성**하고 싶다 | 이름·설명·금액·수량 한정(선택)·예상 전달 시기·배송 필요 여부. 판매된 리워드는 금액 수정 불가 |
| C-5 | 창작자로서 **리워드를 보낼 곳**을 알고 싶다 | 결제 완료된 후원의 받는 사람·연락처·주소 목록 (내 프로젝트만) |

### 관리자 (A)
| ID | 스토리 | 인수 조건 |
|---|---|---|
| A-1 | 관리자로서 문제 있는 프로젝트를 숨기고 싶다 | 숨긴 프로젝트는 목록·상세에서 안 보이고 후원 불가. 관리자만 가능 |
| A-2 | 관리자로서 결제 실패를 살피고 싶다 | 최근 결제 실패 목록(이유 코드 포함) |

## 5. 성공 지표
| 종류 | 지표 | 목표 (가설) |
|---|---|---|
| 핵심 지표 | 상세를 본 방문자 중 후원 완료 비율 | 5% |
| 퍼널 | 상세 → 리워드 선택 → 배송지 → 결제 요청 → 결제 완료 | 가장 큰 이탈 단계 찾기 |
| 보조 | 프로젝트 성공률 / 결제 실패 이유 분포 / 찜 → 후원 전환율 | 관찰 |

## 6. 위험과 대응
| 위험 | 영향 | 대응 |
|---|---|---|
| 마감 시각·시간대 버그로 상태가 틀림 | 신뢰 하락 | 상태 계산을 순수 함수로 만들고 경계값 단위 테스트 (ADR-001) |
| 결제 금액 위조 | 금전 사고 | 서버가 리워드 가격 × 수량 + 추가 후원금으로 총액을 다시 계산해 기록 후 비교·승인 |
| 남은 1개를 두 명이 동시에 결제 → 초과 판매 | 약속 불이행 | 결제 승인 직전 조건부 차감, 실패하면 승인하지 않음, 결과 반영은 트랜잭션 (ADR-003) + 부하 테스트 |
| 결제창에서 돌아오지 못함(브라우저 닫힘) | 돈은 나갔는데 후원 기록 없음 | 토스 웹훅으로 결제 상태를 받아 DB와 맞춤, 같은 알림 중복 처리 방지 |
| 목록이 커지면 느려짐 | 이탈 증가 | 커서 페이지네이션 + 인덱스, EXPLAIN ANALYZE로 전후 비교 |
| 배송지(개인정보) 노출 | 법적·신뢰 문제 | 해당 프로젝트 창작자에게만, 결제 완료 건만 보여줌 |
| 후원 즉시 결제 → 실패 프로젝트도 돈이 나감 | 실제 서비스라면 환불 필요 | 테스트 결제로만 운영, 케이스 스터디에 한계로 명시 (ADR-002) |
| 혼자 개발해 코드 품질이 흔들림 | 버그 증가 | 브랜치·PR·CI·자동 테스트, PR 셀프 리뷰 체크리스트 |

## 7. 아직 정하지 않은 것

- 창작자 소개 페이지를 따로 둘지
