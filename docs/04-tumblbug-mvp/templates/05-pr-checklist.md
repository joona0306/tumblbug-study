# PR 셀프 리뷰 체크리스트 (5주차부터)

> **PR(Pull Request)**: "이 브랜치의 변경을 main에 합쳐도 될까요?"라는 요청서. 혼자 개발해도 PR을 쓰면
> 변경마다 설명과 검사 기록이 남고, CI가 자동으로 검사해 줍니다. 포트폴리오에서 "어떻게 일하는지"를 보여주는 기록이에요.
>
> 이 내용은 5주차에 프로젝트의 `.github/pull_request_template.md`로 넣어, PR을 만들 때마다 자동으로 채워지게 합니다.

## PR 본문 양식
```markdown
## 무엇을 바꿨나
- (한 줄 요약)

## 왜
- 관련 사용자 스토리: B-3 / 관련 ADR: ADR-00x

## 화면 (바뀐 게 있으면)
- 전/후 스크린샷 또는 짧은 영상

## 확인한 것
- [ ] 로컬에서 직접 눌러봄: (어떤 흐름을)
- [ ] 새 로직에 테스트를 추가함 (또는 필요 없는 이유: )
```

## 합치기 전 셀프 리뷰
**동작**
- [ ] 이 PR이 해결하려는 사용자 스토리의 인수 조건을 모두 만족한다
- [ ] 실패하는 경우(빈 값, 잘못된 값, 권한 없음, 네트워크 실패)를 직접 해봤다

**보안·권한**
- [ ] 브라우저에서 오는 값(폼, 주소, 숨은 칸)을 서버에서 zod로 검사한다
- [ ] "내 것"만 바꾸는 곳에 소유자 조건이 있다
- [ ] 비밀 키·토큰이 코드나 로그에 들어가지 않았다

**품질**
- [ ] CI(코드 검사·타입 검사·테스트·빌드)가 모두 통과했다
- [ ] 로딩·빈 화면·에러 상태가 Figma 시안대로 있다
- [ ] 색·간격은 디자인 토큰(CSS 변수)만 썼다 (색 값을 직접 쓰지 않음)
- [ ] 키보드로 조작 가능하고, 사진에 alt가 있다

**기록**
- [ ] 중요한 결정이 있었다면 ADR을 썼다
- [ ] PR 제목이 "무엇을 했는지" 한 줄로 설명한다 (예: "후원 금액 범위를 서버에서 검사")
