# 4단계: 텀블벅 MVP (최종 프로젝트) — 교재 기획서

**교재 제작 상태**: 초안 (3단계 교재 완성 후 상세화)
**학습 기간**: 2개월 (4~5개월차)
**학습 목표**: 3자 권한 구조 + 모금 상태 흐름을 종합해서 완성하기

## 선수 지식
- 1~3단계 완료 (특히 2단계 결제 연동)

## 문제 정의
> 창작자가 프로젝트(목표 금액 포함)를 등록하면, 후원자가 후원(결제)할 수 있고,
> 목표 금액 달성 여부에 따라 프로젝트 상태가 달라진다.

## 기능 범위 (반드시 이 표를 지킬 것 — 스코프 크립 방지)

| 포함 | 제외 |
|---|---|
| 프로젝트 등록 (제목, 설명, 목표 금액, 마감일) | 정산 자동화 |
| 후원(결제) — 금액 자유 입력 | 목표 미달 시 자동 환불 |
| 목표 금액 진행률(%) 표시 | 리워드 여러 옵션 + 재고 관리 |
| 상태 표시 (모금중 / 성공 / 실패) | 카테고리/추천 알고리즘 |
| 프로젝트 목록/상세 페이지 | 업데이트 글, 댓글 |

## 화면 목록
1. 프로젝트 목록 (전체 노출, 필터 없음)
2. 프로젝트 상세 (진행률, 후원 버튼)
3. 창작자용 프로젝트 등록/관리 화면
4. 후원 결제 화면 (2단계 결제 연동 재사용)

## 데이터 구조 (초안)
```
user    : 1단계의 인증 구조(Better Auth) 재사용
project : id, creator_id, title, description, goal_amount, deadline, status
funding : id, project_id, supporter_id, amount, order_id, payment_key, status, created_at
```

## 결정 필요
- **상태(성공/실패) 계산 방식**: 마감일이 지나면 `goal_amount`와 현재 모금액을 비교해 결정.
  - 방식 A: 화면을 열 때마다 계산 (단순, 별도 도구 불필요)
  - 방식 B: 예약 작업(Vercel Cron)이 하루 1번 DB의 status를 갱신 (운영 학습에 좋음)
  - 3단계 완료 후 결정. 교재에서는 A로 먼저 만들고 B로 개선하는 흐름도 고려

## 주차별 체크리스트

### 4개월차
- [ ] 1주차: 스코프 재확인 / 데이터 모델 설계 / 와이어프레임 4장
- [ ] 2주차: 창작자용 프로젝트 등록/수정 화면
- [ ] 3주차: 공개 목록/상세 페이지 + 진행률 표시
- [ ] 4주차: 중간 시연 (지인에게 보여주기) / 회고

### 5개월차
- [ ] 1주차: 후원(결제) 기능 연동 (2단계 결제 로직 재사용)
- [ ] 2주차: 모금 상태 흐름 구현 (모금중 → 성공/실패)
- [ ] 3주차: 예외 처리 (결제 실패, 마감일 지난 프로젝트 처리 등)
- [ ] 4주차: 배포 / 운영 루프 / 전체 기능 점검 / 회고

## 운영 루프 (5개월차 4주차)
- 예약 작업이 제대로 돌았는지 로그로 확인 (방식 B 선택 시)
- DB 백업·복구 연습: Neon의 특정 시점 복구 기능으로 "실수로 지운 데이터 되살리기"
- 피드백 1건 → 개선 1개 → 다시 배포

## 완료 기준 (Definition of Done)
- [ ] 프로젝트 등록 → 목록 노출 → 후원(결제) → 진행률 반영까지 끊김 없이 동작
- [ ] 마감일이 지난 프로젝트가 목표 금액 달성 여부에 따라 상태가 올바르게 바뀜
- [ ] 창작자/후원자 권한이 분리되어 있음 (타인 프로젝트를 수정할 수 없음)
