2문제·범위·성공 지표
💡 왜 사진은 1장만?사진이 여러 장이면 "순서 바꾸기, 한 장만 지우기, 대표 사진 고르기"가 따라옵니다. 파일 업로드를 처음 배우는 단계에서는 1장으로 흐름 전체(올리기 → 보여주기 → 바꾸기 → 지우기)를 확실히 익히는 게 먼저입니다.
3와이어프레임 + 관계도

와이어프레임은 4장: ① 목록(검색창·필터·카드 격자), ② 상세(사진·가격·판매자·연락 방법·내 상품이면 관리 버튼), ③ 등록/수정 폼, ④ 내 판매 상품.

4디자인: 작은 카드 안의 위계

목록은 휴대폰에서 2열 카드로 보여줍니다. 카드는 작아서 무엇을 크게, 무엇을 작게가 특히 중요해요.

  1. 사진 — 가장 크게. 사진 비율이 제각각이어도 카드 높이가 맞도록 4:3으로 잘라서 보여준다
  2. 제목 — 한 줄. 길면 "…"로 자른다
  3. 가격 — 굵게. 0원은 "나눔 🧡"
  4. 카테고리·상태 — 작고 흐리게. 거래완료는 사진까지 흐리게 해서 한눈에 구분

색·글꼴·모서리는 1단계 디자인 결정표를 그대로 씁니다. 사진에는 대체 텍스트(alt)로 상품 제목을 넣기로 정합니다. 화면을 읽어주는 프로그램을 쓰는 사람도 무슨 사진인지 알 수 있게요.

6JavaScript → TypeScript 전환
📖 용어 풀이
  • 타입: 값의 모양. "사과"는 string(글자), 3000은 number(숫자), { email: string }은 "email 칸에 글자가 든 객체".
  • TypeScript: JavaScript에 타입을 적을 수 있게 한 언어. 브라우저·서버에서 실행되기 전에 JavaScript로 바뀌므로, 실행 결과는 같고 실수를 미리 알려주는 기능만 더해집니다.
  • .ts / .tsx: TypeScript 파일. 화면(JSX, <div> 같은 태그)이 들어 있으면 .tsx, 아니면 .ts.
  • strict 모드: 가장 꼼꼼하게 검사하는 설정. "없을 수도 있는 값"을 그냥 쓰면 에러를 냅니다. 처음엔 귀찮지만 실제 버그를 가장 많이 잡아줍니다.

① 타입 도구 설치

@types/…는 "Node.js와 React에 어떤 함수·값이 있는지"를 TypeScript에게 알려주는 설명서 패키지입니다. 버전은 Next.js 16.3.6의 공식 TypeScript 템플릿과 같은 계열로 맞췄어요.

② 파일 이름 바꾸기 (16개)

git mv는 Git 기록을 유지한 채 이름을 바꿉니다. 화면이 있는 파일은 .tsx, 나머지는 .ts입니다.

scripts/migrate.mjs와 eslint.config.mjs는 그대로 둡니다. Node.js가 직접 실행하는 파일이라 TypeScript로 바꾸면 따로 변환 도구가 필요해집니다.

③ 설정 파일 3개

프로젝트 최상위에 tsconfig.json을 만듭니다. create-next-app이 TypeScript 프로젝트에 만들어 주는 것과 같은 내용이에요. 지운 jsconfig.json의 @/ 경로 설정(paths)도 여기 들어 있습니다.

eslint.config.mjs에 TypeScript 규칙(nextTs)을 추가합니다.

④ 타입 검사를 돌리고 에러를 하나씩 고치기

작성자가 실제로 실행했을 때 나온 에러입니다. 여러분도 비슷하게 나올 거예요.

에러가 하는 말번역고치는 법
implicitly has an 'any' type"이 매개변수가 어떤 값인지 모르겠어"타입을 적어준다 (formData: FormData)
'string | undefined' is not assignable to 'string'"환경 변수가 없을 수도 있는데 괜찮아?"없으면 분명한 에러를 내는 함수(requireEnv)를 거친다
'undefined' cannot be used as an index type"에러 코드가 없을 수도 있는데 그걸로 표를 찾아?"코드가 있을 때만 찾는다 (code && …)
💡 이 에러들은 진짜 버그 후보예요.env.local에 DATABASE_URL을 빠뜨리면 JavaScript에서는 한참 뒤에 이해하기 어려운 에러가 났습니다. 이제는 TypeScript가 "없을 수도 있다"를 미리 알려주고, requireEnv가 "환경 변수 DATABASE_URL 이(가) 없습니다"라고 정확히 말해줍니다.

새 파일 lib/env.ts를 만들고, 나머지 파일을 고칩니다.

🆘 놓치기 쉬운 곳drizzle.config.ts 안의 schema: "./db/schema.js"도 .ts로 바꿔야 합니다. 파일 이름을 바꿨는데 설정 안의 글자는 그대로라서, 나중에 drizzle-kit generate가 표를 못 찾습니다. 타입 검사로는 잡히지 않는 실수예요.
📖 코드 읽는 법
  • type AuthFormState = { … } | null — 새 타입에 이름을 붙인다. |는 "또는".
  • username?: string — 물음표는 "없을 수도 있음".
  • Record<string, string> — "글자 키 → 글자 값" 모양의 객체.
  • error: unknown — catch로 잡은 에러는 무엇이 던져졌는지 모르므로 unknown. instanceof로 확인한 뒤에야 안의 값을 쓸 수 있다.
  • Promise<AuthFormState> — "나중에 AuthFormState를 돌려주는 비동기 함수".
✅ 여기까지 됐는지 확인하는 법
  • npx tsc --noEmit이 아무것도 출력하지 않는다 (에러 0개)
  • npm run lint 통과, npm run build에 Finished TypeScript
  • npx drizzle-kit generate → No schema changes, nothing to migrate (TS 설정을 제대로 읽음)
  • 로그인 화면에서 틀린 비밀번호 → 에러 표시, 맞는 비밀번호 → 대시보드 (동작은 JavaScript 때와 똑같다)
🆘 막혔을 때
Module not found: Can't resolve '@/lib/session'

jsconfig.json을 지우고 tsconfig.json을 아직 안 만든 상태입니다. @/ 경로는 tsconfig.json의 paths가 알려줍니다.

VSCode에 빨간 줄이 남아 있어요 (tsc는 통과)

Ctrl+Shift+P → "TypeScript: Select TypeScript Version" → "Use Workspace Version"을 고르고, 창을 다시 불러오세요(Developer: Reload Window).

7판매자 연락 방법 칸 (TypeScript로 첫 기능)

2단계에서 크리에이터 소개(bio)를 추가한 방법 그대로, 이번엔 contact 칸을 추가합니다. 달라진 건 타입을 적는다는 것뿐이에요.

📖 props 에 타입 붙이기type ContactFormProps = { currentContact: string | null | undefined }는 "이 부품을 쓸 때 currentContact를 넘겨야 하고, 그 값은 글자이거나 비어 있을 수 있다"는 약속입니다. 부품을 쓰는 쪽에서 숫자를 넘기거나 빠뜨리면 바로 빨간 줄이 생겨요.
💡 user.contact 에 빨간 줄이 안 생기는 이유우리는 user의 타입을 직접 적지 않았는데도 user.contact를 쓸 수 있습니다. Better Auth가 lib/auth.ts의 additionalFields를 읽어서 로그인 사용자 타입에 contact를 자동으로 넣어주기 때문이에요. 반대로 user.contactt처럼 오타를 내면 즉시 에러가 납니다. 이게 타입의 힘입니다.
✅ 확인하는 법
  • npx tsc --noEmit 에러 0개
  • 내 판매 상품 화면에서 연락 방법 저장 → "저장했어요." → 새로고침해도 유지
  • (실험) contact-form.tsx를 쓰는 곳에서 currentContact={123}으로 바꿔 보면 빨간 줄 → 원래대로 되돌리기
