상품과 사진: 올리고, 보여주고, 바꾸고, 지우기

파일 업로드의 한 바퀴를 모두 경험합니다. 올린 사진을 보여주는 것만큼, 바꾸거나 지울 때 옛 파일을 정리하는 것도 중요합니다.

1상품 표와 상품 규칙 (타입으로 제한하기)
📖 코드 읽는 법
  • text("status", { enum: ["selling", "sold"] }) — 이 칸의 TypeScript 타입이 "selling" | "sold"가 됩니다. 코드에서 "sell"처럼 오타를 내면 빨간 줄.
  • typeof product.$inferSelect — 표 설계도에서 "DB에서 꺼낸 한 줄"의 타입을 뽑아냅니다. 표를 바꾸면 타입도 저절로 바뀌어요.
  • Product["status"] — Product 타입의 status 칸 타입만 꺼내기.
🆘 enum 은 DB를 지켜주지 않아요

만들어진 SQL(drizzle/0002_add_product.sql)을 보면 "status" text일 뿐, "selling과 sold만 허용" 같은 조건이 없습니다. enum은 우리 코드의 타입만 제한해요. 브라우저에서 이상한 값이 오면 여전히 DB에 들어갈 수 있으므로, 3주차에서 서버 검사(타입 가드)를 따로 합니다.

상품 규칙을 한 파일에 모읍니다.

📖 as const 와 타입 가드
  • [...] as const + (typeof CATEGORIES)[number] — 배열에 적은 글자들로 타입을 만듭니다. 카테고리를 하나 추가하면 타입도 자동으로 늘어나요.
  • function isCategory(value: string): value is Category — 타입 가드. true를 돌려주면 TypeScript가 그다음부터 value를 Category로 믿어줍니다. "검사를 통과한 값만 좁은 타입으로" — 서버 검사와 타입이 한 번에 해결됩니다.

2사진 업로드 + 상품 등록 + 상세 페이지

① Vercel Blob 저장소 만들기

  1. Vercel 대시보드 → 상단 Storage → Create → Blob
  2. 이름 my-market-dev, 접근 방식은 Public (상품 사진은 누구나 봐야 하니까)
  3. 만든 저장소의 .env.local 탭(또는 설정)에서 BLOB_READ_WRITE_TOKEN 값을 복사해 내 .env.local에 한 줄 추가
🆘 이 토큰도 비밀번호예요이 토큰이 있으면 저장소의 파일을 올리고 지울 수 있습니다. 채팅·스크린샷에 올리지 말고, 새면 저장소 설정에서 토큰을 다시 만드세요.

② 설정: 요청 크기와 외부 사진 주소

💡 왜 이 두 설정이 필요한가요?
  • bodySizeLimit: 서버 액션은 기본적으로 1MB까지만 받습니다. 줄인 사진은 보통 0.5MB 이하지만 여유를 둡니다. (Vercel 서버는 요청을 최대 4.5MB까지만 받으므로 무작정 키울 수도 없어요.)
  • remotePatterns: Next.js의 <Image>는 아무 주소의 사진이나 받아주지 않습니다. 우리 저장소 주소만 허락해서, 남의 사이트 사진을 우리 서버 자원으로 변환하는 일을 막습니다.

③ 브라우저에서 사진 줄이기

📖 canvas 란?브라우저 안의 보이지 않는 도화지입니다. 큰 사진을 작은 도화지에 그려 넣은 뒤 JPEG로 저장하면 크기가 줄어요. 작성자 검증: 4000×3000 사진 6.86MB → 1280×960 JPEG 130KB.

④ 등록 서버 액션

💡 코드에서 꼭 볼 세 곳
  1. 결과를 두 모양으로: parseProductForm은 { ok: true, data } 또는 { ok: false, error }를 돌려줍니다. if (!parsed.ok) return …을 지나야만 TypeScript가 parsed.data를 쓰게 해줘요. 검사를 깜빡하고 쓰는 실수가 불가능해집니다.
  2. 검사 먼저, 업로드는 나중: 잘못된 입력이면 사진을 올리기 전에 돌려보냅니다. 쓰지도 않을 파일이 저장소에 쌓이지 않게요.
  3. 사진도 서버에서 다시 검사: 브라우저에서 줄였더라도, 누군가 줄이는 과정을 건너뛰고 직접 보낼 수 있으므로 종류(image/)와 크기를 서버가 한 번 더 봅니다.

⑤ 상품 폼 (등록·수정 공용)

app/products 폴더에 만듭니다. 2단계 이후 수정 화면에서도 같은 폼을 씁니다.

📖 왜 폼에 action 대신 onSubmit 을 쓰나요?1·2단계에서는 <form action={formAction}>으로 서버 액션에 바로 연결했습니다. 이번에는 보내기 전에 사진을 줄여야 해서, 제출을 가로채(preventDefault) 사진을 바꿔 끼운 뒤 startTransition(() => formAction(formData))으로 직접 보냅니다.

⑥ 상세 페이지

✅ 여기까지 됐는지 확인하는 법
  1. /products/new에서 휴대폰으로 찍은 큰 사진을 고르면 미리보기가 보인다
  2. 제목·가격·카테고리를 쓰고 등록 → 버튼이 "사진 줄이는 중..." → "저장 중..." → 상세 페이지로 이동
  3. Vercel → Storage → my-market-dev에서 파일 크기를 보면 원본보다 훨씬 작다
  4. (서버 검사) 사진 없이 등록 → "사진을 1장 골라주세요." / F12로 가격 칸의 min을 지우고 -5 → "가격은 0원 이상…" — 두 경우 모두 입력한 제목이 남아 있다
🆘 막혔을 때
Invalid src prop … hostname "….public.blob.vercel-storage.com" is not configured

next.config.ts의 remotePatterns를 확인하고, 설정을 바꿨다면 개발 서버를 껐다 켜세요.

Body exceeded 1 MB limit

bodySizeLimit 설정이 빠졌거나, 사진이 줄지 않고 원본 그대로 갔습니다. handleSubmit에서 resizeImage를 부르는지 확인하세요.

"이 사진은 읽을 수 없어요"

아이폰의 HEIC처럼 브라우저가 못 여는 형식일 수 있습니다. JPG나 PNG로 다시 시도하세요. (아이폰 사파리는 올릴 때 보통 JPEG로 바꿔줍니다)

3상품 목록 (첫 화면)
📖 Awaited<ReturnType<typeof listProducts>>[number]안쪽부터 읽어요. typeof listProducts(이 함수의 타입) → ReturnType(그 함수가 돌려주는 것 = Promise) → Awaited(Promise를 기다린 결과 = 배열) → [number](배열의 한 칸). 즉 "목록 한 줄의 모양"입니다. 조회하는 칸을 바꾸면 이 타입도 저절로 따라옵니다.

목록 카드 부품을 app 폴더에 만듭니다.

💡 minmax(0, 1fr) 은 작성자가 실제로 겪은 버그처음엔 repeat(2, 1fr)로 썼는데, 휴대폰 폭에서 긴 제목이 든 카드가 화면 밖으로 삐져나왔습니다. 1fr 칸은 내용(한 줄로 자른 긴 제목)보다 좁아지지 않기 때문이에요. minmax(0, 1fr)로 "0까지 줄어들어도 된다"고 알려주면 제목이 "…"로 잘리며 칸 안에 들어옵니다.
✅ 확인하는 법
  • 상품을 3~4개 더 올리면 첫 화면에 최신순 2열 카드로 보인다. 0원은 "나눔 🧡"
  • F12 → 휴대폰 화면 모드(Ctrl+Shift+M)에서 긴 제목 카드가 화면 밖으로 넘치지 않는다

4수정·삭제 (본인만, 옛 사진 정리)

서버 액션 파일 맨 아래에 수정·삭제를 추가합니다. (맨 위 import에 del, and, eq, revalidatePath도 추가)

💡 사진을 바꿀 때의 순서새 사진 올리기 → DB에 새 주소 저장 → 그다음에 옛 사진 지우기. 순서를 거꾸로 하면, 새 사진 저장이 실패했을 때 옛 사진은 이미 지워져 상품에 사진이 없어집니다. "되돌릴 수 없는 일은 맨 마지막에"가 원칙이에요.

상세 페이지에 본인에게만 보이는 수정·삭제 버튼을 붙입니다.

✅ 여기까지 됐는지 확인하는 법
  1. 내 상품 상세에는 "수정·삭제" 버튼, 시크릿 창의 다른 계정으로 보면 버튼 없음
  2. 다른 계정으로 /products/내상품번호/edit 직접 접속 → "페이지를 찾을 수 없어요"
  3. 수정 화면에 원래 값이 채워져 있고, 사진을 새로 골라 저장하면 상세에 새 사진
  4. Vercel Blob 저장소 목록에서 옛 사진 파일이 사라졌다
  5. 삭제 → 확인창 → "내 판매 상품"으로 이동, 저장소에서도 사진이 사라졌다
🆘 지웠는데 사진 주소가 아직 열려요

정상입니다. Vercel Blob은 사진을 전 세계 캐시 서버(CDN)에 복사해 빠르게 나눠 주는데, 원본을 지워도 캐시에는 잠시 남아 있을 수 있어요. 저장소 목록에서 파일이 사라졌다면 삭제는 된 것입니다. (작성자 검증에서도 삭제 직후 주소는 열렸지만 저장소 목록에는 없었습니다)

🧪 도전: 남의 상품 고치기다른 계정으로 로그인해 자기 상품 수정 화면을 열고, F12로 숨은 칸 name="id"의 값을 남의 상품 번호로 바꿔 저장 → "수정할 수 없는 상품입니다." 남의 상품은 그대로여야 합니다.
