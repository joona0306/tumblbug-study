배포하고, 저장소까지 운영하기

이번에는 운영할 대상이 DB 하나가 아니라 DB + 파일 저장소 두 개입니다. 둘이 서로 맞는지(사진 주소 ↔ 실제 파일) 점검하는 법을 배웁니다.

1운영용 저장소 나누기 (DB와 사진)

1단계에서 DB를 개발용/운영용으로 나눈 것처럼, 사진 저장소도 나눕니다. 개발하면서 올린 테스트 사진이 운영 저장소에 섞이지 않게요.

개발 (내 컴퓨터)운영 (Vercel)
DBNeon my-market의 dev 브랜치기본 브랜치 (production/main)
사진Blob my-market-dev (2주차에 만든 것)Blob my-market-prod (새로 만듦, Public)
설정 위치.env.localVercel 환경 변수
  1. GitHub에 새 저장소 my-market을 만들고 push (1단계 방법)
  2. Neon dev 브랜치를 만들고 .env.local을 dev 주소로 교체, 기본 브랜치의 테스트 데이터 정리 (1단계 방법)
  3. Vercel Storage에서 Blob 저장소 my-market-prod를 Public으로 만든다
🆘 DB를 정리하면 개발 저장소에 사진이 남아요

기본 브랜치에서 DELETE FROM "user";를 하면 상품 줄은 지워지지만, 그 사진 파일은 my-market-dev 저장소에 남습니다(개발 중에 올린 것이니까요). 개발 저장소는 테스트용이라 그대로 둬도 되고, 4단계의 점검 스크립트로 정리해도 됩니다.

2Vercel 배포
  1. vercel.com/new에서 my-market Import, 환경 변수 3개: DATABASE_URL(Neon 기본 브랜치), BETTER_AUTH_SECRET(새 운영용), BETTER_AUTH_URL(https://my-market.vercel.app, 배포 후 실제 주소로 맞추기)
  2. Deploy
  3. 배포된 프로젝트의 Storage 탭 → Connect Store → my-market-prod 연결. 연결하면 운영 환경 변수 BLOB_READ_WRITE_TOKEN이 자동으로 들어갑니다
  4. 환경 변수가 추가되었으니 Deployments → Redeploy
✅ 확인하는 법
  • 빌드 로그에 Finished TypeScript와 [migrate] 운영 DB 마이그레이션 완료 (기록 3개: init, add_contact, add_product)
  • 휴대폰으로 운영 주소에 가입 → 휴대폰 카메라 사진으로 상품 등록 → 목록·상세에 사진
  • 그 사진이 my-market-prod 저장소에 올라갔다 (my-market-dev가 아니라)
🆘 막혔을 때
빌드가 타입 에러로 실패해요

Vercel도 빌드할 때 tsc와 같은 타입 검사를 합니다. 내 컴퓨터에서 npm run build가 통과하는지 먼저 확인하고 push하세요. 타입 에러가 있는 코드는 배포되지 않습니다 — TypeScript의 또 다른 안전장치예요.

등록할 때 "No token found" 같은 에러

운영 프로젝트에 Blob 저장소가 연결되지 않았거나, 연결 후 다시 배포하지 않았습니다. Storage 탭에서 연결을 확인하고 Redeploy 하세요.

3측정: 거래완료율

Neon SQL Editor(기본 브랜치)에서 두 덩어리를 하나씩 실행합니다. 작성자 검증 데이터: 7개 중 1개 거래완료 → 14.3%, 카테고리별 등록·거래완료 수 집계.

💡 거래완료율이 낮다면판매자가 팔고 나서 상태를 안 바꿨을 수도 있어요(측정의 함정). 사용성 테스트에서 "팔린 뒤에 무엇을 하는지" 관찰해 보면, 지표가 진짜 문제인지 측정 방식의 문제인지 구분할 수 있습니다.
4운영 루프: 고아 사진 점검과 저장 용량
📖 고아 사진저장소에는 있는데 DB의 어떤 상품도 쓰지 않는 사진. 사진을 올린 직후 DB 저장이 실패했거나, 코드 실수로 옛 사진을 안 지우면 생깁니다. 아무도 안 보는데 저장 용량(=비용)만 차지해요.

DB의 사진 주소 목록과 저장소의 파일 목록을 비교하는 점검 스크립트를 만듭니다.

운영 환경을 점검하려면 운영 DB 주소와 운영 저장소 토큰을 담은 .env.production.local을 만들어(이름이 .env로 시작해서 Git에 안 올라감) 그 파일로 실행합니다. 먼저 --delete 없이 결과를 보고, 지워도 되는지 확인한 뒤에만 지우세요.

✅ 확인하는 법 (작성자 검증 순서)
  1. 처음 실행: 저장소 사진 7개 / DB 상품 7개 / 고아 사진 0개
  2. 테스트로 저장소에 파일 1개를 직접 올린 뒤 실행 → 고아 사진 1개와 그 경로가 나온다
  3. --delete로 실행 → "고아 사진 1개를 지웠습니다." → 다시 실행하면 0개

저장 용량은 Vercel → Storage → 저장소 화면에서 볼 수 있습니다. 무료 사용량을 넘기 전에 알 수 있게 가끔 확인하세요.

5사용성 테스트 + 접근성 점검

방법은 1단계 4주차 7단계와 같습니다. 과제는 이렇게 줍니다.

  1. 안 쓰는 물건 하나를 사진 찍어서 올려 주세요
  2. 도서 중에서 팔리는 중인 것만 찾아 주세요
  3. 마음에 드는 물건의 판매자에게 연락하는 방법을 찾아 주세요 (로그인 안 한 상태에서 시작)
  4. 올린 물건이 팔렸다고 치고 표시해 주세요

접근성: 작성자가 실제로 발견한 문제

Lighthouse로 점검했더니 첫 화면만 96점이 나왔습니다. 원인은 링크 글자의 명도 대비였어요. 1단계에서는 링크가 흰 카드(#ffffff) 위에 있어서 4.55로 겨우 통과했는데, 3단계 첫 화면에서는 링크가 조금 더 어두운 페이지 배경(#f7f7f8) 위에 놓이면서 4.25로 기준(4.5) 아래가 됐습니다. 메인 색을 조금 어둡게 바꿔 해결했습니다.

💡 배운 점대비는 "색 하나"가 아니라 "글자색 + 그 뒤의 배경색" 짝의 성질입니다. 같은 색이라도 놓이는 자리가 바뀌면 다시 확인해야 해요. 수정 후 첫 화면·필터·상세·등록·수정·내 판매 상품·로그인 모두 100점.

그 밖에 확인할 것:

  • 모든 상품 사진에 alt(상품 제목)가 있다 — 화면 읽기 프로그램이 "원목 책상"이라고 읽어줌
  • Tab만으로 검색어 입력 → 카테고리 선택 → 판매중 체크 → 검색, 상품 등록(파일 선택 포함)이 된다
6개선 1개 + 4단계(텀블벅) 준비

1·2단계처럼 지표 → 관찰 → 가설 → 수정 → 재측정을 한 바퀴 돕니다. 개선 후보 예: "스위치"로 영어 제목 찾기, 팔린 뒤 상태를 바꾸도록 알려주는 안내, 가격 입력 시 쉼표 표시.
