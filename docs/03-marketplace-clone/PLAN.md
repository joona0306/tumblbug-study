# 3단계: 당근마켓 미니 클론 — 교재 기획서

**교재 제작 상태**: 초안 (2단계 교재 완성 후 상세화)
**학습 기간**: 1개월 (1~4주차)
**학습 목표**: 1:N 데이터 관계, 검색/필터, 상태값(status), 파일(이미지) 업로드 다루는 법 익히기

## 선수 지식
- 1~2단계 완료

## 문제 정의
> 동네 중고거래처럼, 사용자가 상품을 올리고 다른 사용자가 검색/필터로 찾아
> 연락처를 확인할 수 있게 한다. (채팅 기능은 제외 — 연락처만 공개)

## 기능 범위

| 포함 | 제외 |
|---|---|
| 상품 등록/수정/삭제 (이미지 1장) | 채팅 기능 |
| 상품 목록 + 검색 | 위치 기반(동네 인증) |
| 카테고리 필터 | 알림(찜하기 알림 등) |
| 판매 상태 표시 (판매중/거래완료) | 신고/차단 기능 |

## 화면 목록
1. 상품 목록 (검색창 + 카테고리 필터)
2. 상품 상세 페이지
3. 상품 등록/수정 화면 (본인 상품만)

## 데이터 구조 (초안)
```
user    : 1단계의 인증 구조(Better Auth) 재사용 + 연락처 필드
product : id, user_id, title, price, category, status, image_url, created_at
```

## 결정 필요
- **이미지 저장소**: Neon은 DB만 제공하므로 파일을 저장할 곳이 따로 필요함.
  후보: Vercel Blob(설정이 가장 간단) / Cloudflare R2(무료 용량이 큼). 2단계 완료 후 결정

## 주차별 체크리스트
- [ ] 1주차: 기획 / Product-User 관계 설계 (1:N 개념 학습) / 와이어프레임
- [ ] 2주차: 상품 등록/목록/상세 페이지 구현 (이미지 업로드 포함)
- [ ] 3주차: 검색, 카테고리 필터, 상태값(판매중/거래완료) 구현
- [ ] 4주차: 배포 / 운영 루프 / 회고 / 텀블벅 기능 목록 미리 정리

## 운영 루프 (4주차)
- 1단계에서 배운 사용량 측정(Vercel Analytics + SQL 지표)으로 검색·필터가 실제로 쓰이는지 숫자로 확인
- 가장 많이 쓰이는(또는 안 쓰이는) 기능 1개를 골라 개선 → 다시 배포

## 완료 기준 (Definition of Done)
- [ ] 상품 등록 후 목록에서 검색/필터로 정상 조회됨
- [ ] 판매 상태를 변경하면 목록/상세 화면에 즉시 반영됨
- [ ] 본인 상품만 수정/삭제 가능하고 타인 상품은 불가능함 (서버에서 권한 검사)
