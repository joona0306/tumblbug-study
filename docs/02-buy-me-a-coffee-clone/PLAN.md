# 2단계: Buy Me a Coffee 클론 — 교재 기획서

**교재 제작 상태**: 정답 코드·HTML 교재 완성 (코드 실행 검증 완료, 결제 승인 성공 경로는 작성자 테스트 결제 2회로 확인. Vercel 배포 절차는 작성자 첫 실행 시 확인 예정)
**학습 기간**: 1개월 (1~4주차)
**학습 목표**: 1단계 코드를 재사용해 새 서비스를 시작하는 법 + 결제 연동을 처음으로 다뤄보기.
특히 **"결제 승인은 반드시 서버에서, 금액은 서버가 정한다"**는 원칙을 직접 구현하며 이해하기

## 선수 지식
- 1단계 완료 (Next.js 서버 액션, Drizzle, Better Auth, Vercel 배포, 측정·개선 사이클)
- 계정: 토스페이먼츠 개발자센터 (가입 전에는 문서에 공개된 테스트 키로 시작 가능)

## 문제 정의
> 크리에이터가 후원 페이지를 만들고, 팬이 소액 후원(커피 한 잔 값)을 보낼 수 있게 한다.

## 기능 범위

| 포함 | 제외 |
|---|---|
| 크리에이터 프로필 페이지 (한 줄 소개 포함) | 크리에이터 정산 자동화 |
| 후원 금액 선택 (3,000 / 5,000 / 10,000원) | 정기 후원(구독), 금액 직접 입력 |
| 토스페이먼츠 결제위젯 테스트 결제 연동 | 실제 카드 결제(라이브 모드), 환불 |
| 후원 내역 + 후원자 이름·메시지 표시 | 후원자 랭킹/뱃지, 후원자 로그인 |
| 크리에이터 대시보드 (받은 후원 합계·목록, 소개 수정) | 알림(이메일/카카오톡) |

- 후원자는 **로그인 없이** 이름(선택)과 메시지만 남긴다. 로그인은 크리에이터만 한다.

## 화면 목록
1. 크리에이터 공개 프로필 `/[username]` — 소개, 후원 금액 선택 + 결제위젯, 후원 내역
2. 결제 성공 `/support/success` / 실패 `/support/fail`
3. 크리에이터 대시보드 `/dashboard` — 받은 후원 합계·목록, 소개 수정
4. 회원가입 / 로그인 (1단계 재사용)

## 데이터 구조
```
user    : 1단계 Better Auth 구조 재사용 + bio(한 줄 소개)
support : id, creator_id, supporter_name, amount, message,
          order_id(고유), payment_key, status(pending/paid/failed), fail_reason,
          created_at, paid_at
```
- 결제 흐름: 결제 요청 직전에 서버가 `pending` 줄을 만들며 **금액을 서버가 기록** →
  결제 후 돌아오면 서버가 DB 금액과 비교 → 토스에 승인 요청 → 성공 시 `paid`, 실패 시 `failed`

## 성공 지표
- **결제 시도 대비 결제 완료 비율** (pending 으로 시작된 후원 중 paid 가 된 비율) —
  후원하려던 사람이 중간에 포기하지 않고 끝까지 갔는지를 보여줌

## 주차별 체크리스트
- [ ] 1주차: 경쟁 서비스 분석 / 문제·범위·성공 지표 / 와이어프레임 + 결제 흐름 그림 / 디자인 결정 재사용·조정 /
  1단계 코드 가져와 새 프로젝트 시작 / 크리에이터 소개·공개 프로필 뼈대
- [ ] 2주차: 토스페이먼츠 테스트 연동 — support 표 → 결제 요청(서버가 금액 기록) → 결제위젯 → 서버 승인 → 실패 처리
- [ ] 3주차: 후원 내역·메시지 표시, 크리에이터 대시보드(합계·목록·소개 수정), 금액 조작 방어 확인
- [ ] 4주차: 배포 / 사용량·지표 측정 / 운영 루프(결제 실패 추적) / 테스트 결제 10회 이상 / 사용성·접근성 / 지표 기반 개선 / 회고

## 운영 루프 (4주차)
- 에러 처리: 결제 실패·취소·금액 조작 시도 시 사용자에게 보여줄 화면과 서버 로그 남기기
- 결제 실패 추적: `status = failed`인 후원 건을 SQL로 모아 원인(fail_reason) 확인
- 지표 확인 → 사용성 테스트 → 가설 → 개선 1개 → 재측정

## 완료 기준 (Definition of Done)
- [ ] 테스트 결제가 실제로 승인 완료되고 DB에 `paid`로 기록됨
- [ ] 프로필 페이지에서 후원 내역과 메시지가 정상 노출됨
- [ ] 결제 실패 시나리오(취소 등)에서도 에러 없이 처리되고 `failed`로 기록됨
- [ ] 성공 주소의 금액을 바꿔 요청해도 서버에서 걸러짐
- [ ] 테스트 결제 10회 이상 직접 진행, 성공 지표 계산
- [ ] 키보드만으로 후원 흐름이 가능하고, Lighthouse 접근성 90점 이상
