# 2단계: Buy Me a Coffee 클론 — 교재 기획서

**교재 제작 상태**: 초안 (1단계 교재 완성 후 상세화)
**학습 기간**: 1개월 (1~4주차)
**학습 목표**: 로그인 흐름 복습 + 결제 연동을 처음으로 다뤄보기.
특히 "결제 승인은 반드시 서버에서 한다"는 원칙을 이해하기

## 선수 지식
- 1단계 완료 (Next.js 서버 액션, Drizzle, Better Auth, Vercel 배포)
- 계정: 토스페이먼츠 개발자 계정 (테스트 키)

## 문제 정의
> 크리에이터가 후원 페이지를 만들고, 팬이 소액 후원(커피 한 잔 값)을 보낼 수 있게 한다.

## 기능 범위

| 포함 | 제외 |
|---|---|
| 크리에이터 프로필 페이지 | 크리에이터 정산 자동화 |
| 후원 금액 선택 (예: 3,000 / 5,000 / 10,000원) | 정기 후원(구독) |
| 토스페이먼츠 테스트 결제 연동 | 실제 카드 결제(라이브 모드) |
| 후원 내역 + 후원자 메시지 표시 | 후원자 랭킹/뱃지 |

## 화면 목록
1. 크리에이터 프로필 페이지 (공개)
2. 후원 금액 선택 + 결제 화면
3. 결제 성공 / 실패 화면
4. 후원 내역 목록 (프로필 페이지 하단)

## 데이터 구조 (초안)
```
user    : 1단계의 인증 구조(Better Auth) 재사용
support : id, creator_id, supporter_name, amount, message,
          order_id, payment_key, status(pending/paid/failed), created_at
```
- `order_id`, `payment_key`, `status`는 결제 승인 흐름에 필요해서 추가
  (결제 요청 시 pending으로 저장 → 서버에서 승인 성공 시 paid로 변경)

## 주차별 체크리스트
- [ ] 1주차: 기획 / 크리에이터 프로필 화면 설계 / 1단계 인증 구조 가져오기
- [ ] 2주차: 토스페이먼츠 테스트 모드 연동 (결제 요청 → 서버에서 승인 흐름 이해)
- [ ] 3주차: 후원 내역 저장, 프로필 페이지에 표시, 후원자 메시지 기능
- [ ] 4주차: 배포 / 운영 루프 / 테스트 결제 10회 이상 직접 진행 / 회고

## 운영 루프 (4주차)
- 에러 처리: 결제 실패·취소·금액 조작 시도 시 사용자에게 보여줄 화면과 서버 로그 남기기
- 결제 실패 추적: `status = failed`인 후원 건을 모아 보고 원인 확인하기
- 피드백 1건 → 개선 1개 → 다시 배포

## 완료 기준 (Definition of Done)
- [ ] 테스트 결제가 실제로 승인 완료되고 DB에 기록됨
- [ ] 프로필 페이지에서 후원 내역과 메시지가 정상 노출됨
- [ ] 결제 실패 시나리오(취소 등)에서도 에러 없이 처리됨
- [ ] 브라우저에서 금액을 바꿔 요청해도 서버에서 걸러짐
