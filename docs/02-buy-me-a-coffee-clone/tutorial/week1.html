기획하고, 1단계 코드 위에 새 서비스 세우기

1단계에서 익힌 기획·디자인 과정을 빠르게 한 번 더 하고, 결제가 들어가는 서비스답게 결제 흐름을 먼저 그림으로 설계합니다. 주 후반에는 1단계 코드를 복사해서 새 프로젝트를 시작합니다.

1경쟁 서비스 3개 써보기
서비스주소볼 것
Buy Me a Coffeebuymeacoffee.com이번에 따라 만들 대상. 후원 금액 고르는 방식, 메시지
Ko-fiko-fi.com비슷한 해외 서비스. 후원 후 감사 화면
투네이션toon.at한국 방송인 후원 서비스. 한국 결제수단

결제까지 해볼 필요는 없어요. 크리에이터 페이지를 몇 개 둘러보며 1단계처럼 캡처하고 비교표를 채우세요. 이번에는 이 질문에 집중합니다.

  • 후원하기 전에 무엇을 입력하게 하나? (이름, 메시지, 금액)
  • 후원자가 로그인해야 하나?
  • 후원이 끝나면 어떤 화면이 나오나? 후원 내역은 어디에 보이나?
2문제·범위·성공 지표
💡 왜 금액을 직접 입력하지 못하게 하나요?금액을 고정된 3가지로만 받으면 서버가 "이 목록에 있는 금액인가?"만 검사하면 됩니다. 직접 입력을 허용하면 최소·최대 금액, 소수점, 음수 같은 경우를 모두 막아야 해서 첫 결제 연동으로는 어렵습니다. 범위를 좁히는 것도 설계입니다.
💡 왜 이 지표인가요?결제는 단계가 많아서 중간에 포기하기 쉽습니다(결제수단 고르기, 인증, 비밀번호…). "후원하기를 누른 사람 중 몇 %가 끝까지 갔나"를 보면 결제 과정 어딘가가 불편한지 알 수 있어요. 4주차에 실제 데이터로 계산합니다.
3와이어프레임 + 결제 흐름 설계

와이어프레임은 3장입니다: ① 크리에이터 공개 페이지(소개 + 후원 폼 + 후원 내역), ② 결제 성공/실패 화면, ③ 크리에이터 대시보드. 그리는 법은 1단계 1주차와 같아요.

이번에는 화면보다 중요한 그림이 하나 더 있습니다. 후원 1건이 어떤 상태를 거치는지입니다.

📖 용어 풀이상태값(status): 한 데이터가 여러 단계를 거칠 때 "지금 어느 단계인지"를 적어 두는 칸. 가능한 값을 미리 정해 두고(pending/paid/failed), 어떤 조건에서 어느 값으로 바뀌는지 그림으로 먼저 정하면 코드가 단순해집니다.
4디자인 결정 재사용하기

1단계의 디자인 결정표(색·글꼴·모서리)를 그대로 가져갑니다. 같은 사람이 만든 서비스들이 비슷한 느낌을 주는 것도 "일관성"이에요. 새로 정할 것은 두 가지뿐입니다.

  • 금액 선택 버튼: 1단계의 둥근 알약 모양을 재사용하되, 선택된 것은 메인 색 테두리로 강조
  • 결제위젯: 토스페이먼츠가 그려주는 영역이라 색을 바꿀 수 없어요. 다크 모드에서도 흰 상자로 보이는 것이 정상입니다.
💡 브랜드 색을 커피색으로 바꾸고 싶다면--primary만 바꾸면 됩니다. 다만 1단계에서 배운 대로 버튼 글자와의 대비 4.5:1을 꼭 확인하세요. 갈색처럼 어두운 색은 흰 글씨와 대비가 좋지만, 베이지처럼 밝은 색은 버튼 글자를 검정으로 바꿔야 합니다.
51단계 코드를 가져와 새 프로젝트 시작

회원가입·로그인·로그아웃, DB 연결, 배포 설정은 1단계와 똑같이 필요합니다. 처음부터 다시 만들지 않고 1단계 프로젝트를 복사한 뒤 링크 기능만 걷어냅니다.

💡 복사해도 되나요?실제 회사에서도 새 서비스를 시작할 때 검증된 코드(로그인, 배포 설정)를 가져다 씁니다. 대신 무엇을 남기고 무엇을 지우는지 알고 해야 해요. 이 단계가 그 연습입니다.

① 복사하고 새 저장소로 만들기

git clone으로 복사하면 Git에 올라간 파일만 복사되어 node_modules, .env.local이 따라오지 않습니다. rm -rf .git으로 1단계의 저장 기록을 지우고 새로 시작합니다.

② 링크 기능 걷어내기

남기는 것 (재사용)지우는 것
로그인: lib/auth.js, lib/session.js, app/actions/auth.js, app/signup, app/login, app/api/auth링크: 서버 액션, 추가 폼, 목록 부품, 규칙 파일
DB 연결: db/index.js, db/auth-schema.js, drizzle.config.js공개 페이지 app/[username] (새로 만듦)
배포·운영: scripts/migrate.mjs, vercel.json, /api/health, Analytics1단계 마이그레이션 기록 drizzle/, 지표 SQL sql/ (새 DB에 맞게 다시 만듦)

남은 파일 중 링크를 쓰던 곳을 고칩니다. db/schema.js에서 링크 표를 뺍니다.

대시보드는 인사와 로그아웃만 남깁니다.

첫 화면과 사이트 제목을 바꿉니다.

app/globals.css에서 .link-list {로 시작하는 줄부터 파일 끝까지 지웁니다. (링크 목록·공개 페이지 전용 스타일) 마지막이 button.danger { … } 블록으로 끝나면 됩니다.

③ 새 DB 만들고 연결하기

  1. Neon에서 새 프로젝트 my-coffee를 만듭니다 (Singapore, 추가 기능 모두 끔 — 1단계 2주차와 같음)
  2. 프로젝트 최상위에 .env.local을 새로 만듭니다. 비밀키는 1단계와 다른 값으로 새로 만드세요.

빈 DB에 로그인 표를 만듭니다. 링크 표가 빠진 새 마이그레이션 기록이 생겨요.

✅ 여기까지 됐는지 확인하는 법
  • npm run lint에 에러가 없다 (지운 파일을 아직 import 하는 곳이 있으면 여기서 드러남)
  • Neon Tables에 account, session, user, verification 4개만 있다 (link 없음)
  • 첫 화면에 "☕ Buy Me a Coffee", 회원가입 → 대시보드 "크리에이터 대시보드 / 안녕하세요, ○○님!"
🆘 막혔을 때
Module not found: Can't resolve '@/lib/links'

로그인했는데 바로 로그아웃돼요

6크리에이터 소개 + 공개 프로필 (표에 칸 추가하기)

크리에이터가 "한 줄 소개"를 쓸 수 있게 user 표에 bio 칸을 추가합니다. 이미 쓰고 있는 표의 구조를 바꾸는 첫 경험이에요.

① 설정에 칸 추가 → 설계도 다시 만들기 → DB에 반영

lib/auth.js에 user.additionalFields를 추가합니다.

drizzle/0001_add_bio.sql을 열어보면 딱 한 줄입니다: ALTER TABLE "user" ADD COLUMN "bio" text; — "user 표에 bio 칸을 추가해"라는 뜻이에요. 기존 사용자 데이터는 그대로 두고 칸만 늘어납니다.

💡 왜 input: false 인가요?가입할 때 소개까지 받으면 가입 화면이 길어집니다. input: false는 "가입 API로는 이 값을 받지 않는다"는 뜻이라, 누가 가입 요청에 bio를 몰래 끼워 넣어도 무시됩니다. 소개는 로그인한 뒤 대시보드에서만 바꿀 수 있어요.
