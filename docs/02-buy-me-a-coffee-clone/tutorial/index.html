1단계와 비교해 새로 배우는 것

주제한 줄 설명
코드 재사용1단계 프로젝트를 복사해서 로그인 구조는 그대로 두고, 필요 없는 기능만 걷어내기
표 구조 바꾸기이미 쓰고 있는 표에 칸을 추가하는 마이그레이션 (1단계 4주차에서 예고한 것)
결제 연동토스페이먼츠 결제위젯, 결제 요청 → 인증 → 서버에서 승인
금액 위조 방어금액은 서버가 정하고 기록한다. 브라우저가 보낸 금액은 비교용일 뿐
상태값한 건의 후원이 pending → paid / failed로 바뀌는 흐름 관리
운영: 실패 추적결제가 왜 실패했는지 이유를 기록하고 SQL로 모아 보기

큰 그림: 결제는 세 곳이 주고받는 대화

이번 단계의 모든 코드는 아래 그림의 어느 한 화살표에 해당합니다. 특히 ②와 ⑥⑦이 서버에서 일어난다는 점이 핵심이에요.

📖 용어 풀이
  • PG(결제 대행사): 카드사·은행과 가게 사이에서 결제를 대신 처리해주는 회사. 토스페이먼츠가 여기에 해당합니다.
  • 클라이언트 키 / 시크릿 키: 클라이언트 키는 브라우저에 공개해도 되는 "가게 이름표", 시크릿 키는 서버만 알아야 하는 "도장"입니다. 승인(⑦)은 시크릿 키가 있어야 할 수 있어요.
  • 테스트 모드: test_로 시작하는 키로 한 결제는 모두 가상입니다. 실제 돈이 움직이지 않아요.

시작하기 전

💡 개발자센터에 가입하면 좋은 점교재는 토스페이먼츠 문서에 공개된 테스트 키로 진행합니다. 누구나 같은 키를 쓰기 때문에 결제 기록을 따로 볼 수는 없어요. 가입하면 내 전용 테스트 키를 받고, 개발자센터에서 내 테스트 결제 내역과 로그를 볼 수 있습니다. 4주차 운영 루프에서 특히 도움이 됩니다.

주차별로 이동하기

지금 할 차례 2주차 결제 연동 후원 표, 결제위젯, 서버 승인, 실패·취소 처리
지금 할 차례 3주차 후원 내역과 대시보드 후원 목록·메시지, 합계, 내 서비스 공격해보기
지금 할 차례 4주차 배포와 운영 배포, 테스트 결제 10회, 실패 추적, 지표 기반 개선

이 단계를 끝냈다는 기준

  • 테스트 결제가 실제로 승인 완료되고 DB에 paid로 기록된다
  • 프로필 페이지에서 후원 내역과 메시지가 정상적으로 보인다
  • 결제를 취소하거나 실패해도 에러 없이 처리되고, 이유와 함께 failed로 기록된다
  • 성공 주소의 금액을 바꿔도 서버가 걸러낸다
  • 테스트 결제를 10회 이상 해보고, 성공 지표(결제 완료율)를 계산한다
  • 키보드만으로 후원할 수 있고, Lighthouse 접근성 90점 이상
