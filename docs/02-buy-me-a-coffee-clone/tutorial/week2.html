결제 연동: 요청 → 인증 → 서버 승인

이번 주의 원칙은 하나입니다. "금액은 서버가 정하고, 승인도 서버가 한다." 시작 페이지의 결제 흐름도를 옆에 띄워두고 따라오세요.

단계흐름도에서끝나면 되는 것
1 후원 표②의 "주문 저장" 자리DB에 support 표가 생긴다
2 결제 요청 + 위젯①②③④결제창이 뜨고, DB에 pending 주문이 생긴다
3 서버 승인⑤⑥⑦⑧⑨⑩테스트 결제가 끝까지 완료되고 paid로 기록된다
4 실패·취소⑨의 failed 쪽결제창을 닫거나 실패해도 이유와 함께 기록된다
1후원(support) 표 만들기

1주차에 그린 상태 변화도를 표로 옮깁니다. 후원 1건 = 한 줄이고, 크리에이터 1명이 후원을 여러 건 받습니다(1 : N).

📖 칸 이름 풀이
  • order_id: 우리가 만드는 주문 번호. 토스와 우리가 같은 주문을 가리킬 때 씁니다. unique라 겹칠 수 없어요.
  • payment_key: 결제가 끝나면 토스가 알려주는 결제 번호. 나중에 환불하거나 결제를 조회할 때 필요해서 저장해 둡니다.
  • amount: 서버가 확인한 금액. 결제 후 이 값과 비교합니다.
  • fail_reason: 실패했을 때 그 이유. 4주차 운영 때 "왜 실패했나"를 모아 봅니다.

후원 규칙은 한 파일에 모읍니다. 화면과 서버가 같은 금액 목록을 씁니다.

✅ 확인하는 법Neon Tables에 support 표가 생기고, status 칸의 기본값이 pending이다.

2결제 요청 + 결제위젯

① 키를 어디에 두나

.env.local에 두 줄을 추가합니다. 아래 값은 토스페이먼츠 문서에 누구나 쓰라고 공개된 테스트 키입니다. 개발자센터에 가입했다면 [API 키] 메뉴의 결제위젯 연동 키(test_gck_, test_gsk_로 시작)로 바꿔도 됩니다.

🆘 키는 짝이 맞아야 해요

결제위젯은 결제위젯 연동 키(gck/gsk)를 씁니다. 개발자센터의 "API 개별 연동 키"(ck/sk)를 넣으면 위젯이 제대로 동작하지 않아요. 또 클라이언트 키와 시크릿 키는 같은 종류·같은 계정의 짝이어야 승인이 됩니다.

② 토스페이먼츠 SDK 설치

③ 결제 요청 서버 액션 (흐름도 ②③)

"후원하기"를 누르면 결제창보다 먼저 이 함수가 서버에서 실행됩니다. 금액을 검사하고, 주문을 pending으로 저장한 뒤 주문 번호를 돌려줍니다.

💡 왜 결제 전에 저장하나요?결제창이 열린 뒤에는 금액을 바꿀 기회가 브라우저에 있습니다. 그래서 결제창을 열기 전에 서버가 "이 주문은 3,000원"이라고 먼저 적어 둡니다. 결제가 끝나고 돌아왔을 때 이 기록과 비교하면 위조를 알아챌 수 있어요(3단계).

④ 후원 폼 + 결제위젯 (흐름도 ①④)

app/[username] 폴더에 후원 폼 부품을 만듭니다.

📖 코드 읽는 법
  • useEffect: "화면이 그려진 뒤에 이 일을 해줘". 결제위젯은 브라우저 화면에 그려야 해서 화면이 준비된 뒤에 불러옵니다. 두 번째 인자 [widgets]는 "widgets 값이 바뀔 때마다 다시 실행"이라는 뜻입니다.
  • ANONYMOUS: 후원자는 로그인하지 않으므로 "비회원 결제"로 위젯을 만듭니다.
  • requestPayment: 결제창을 엽니다. 결제가 끝나면 토스가 successUrl 또는 failUrl로 브라우저를 보냅니다.

공개 프로필에 후원 폼을 붙입니다.

app/globals.css 맨 아래에 후원 폼 스타일을 추가합니다. 원래의 동그란 라디오 버튼을 숨기고 알약 모양으로 보이게 하되, 키보드로 고를 수 있게 남겨 둡니다.

✅ 여기까지 됐는지 확인하는 법
  1. 내 공개 페이지(/내이름)에 금액 버튼 3개, 이름·메시지 칸, 그리고 "테스트 환경이에요. 실제로 결제되지 않아요."가 적힌 결제위젯이 보인다
  2. 금액을 바꾸면 버튼 글자가 "5,000원 후원하기"처럼 바뀐다
  3. "후원하기" → 토스 결제창이 뜬다. 아직 끝까지 결제하지 말고 결제창 왼쪽 위 <를 눌러 닫는다 → 폼에 "취소되었습니다."
  4. Neon → Tables → support에 방금 누른 만큼 pending 줄이 생겨 있다 (결제창을 닫아도 pending으로 남는 문제는 4단계에서 고칩니다)
🆘 막혔을 때
버튼이 계속 "결제 준비 중..."이에요

F12 Console에 빨간 에러를 확인하세요. 클라이언트 키가 비어 있으면(undefined) 위젯을 못 불러옵니다. .env.local의 이름이 정확히 NEXT_PUBLIC_TOSS_CLIENT_KEY인지 확인하고 개발 서버를 껐다 켜세요. NEXT_PUBLIC_ 값은 서버를 켤 때 코드에 박혀 들어갑니다.

위젯 대신 "지원하지 않는 키" 같은 오류가 보여요

API 개별 연동 키(test_ck_)를 넣은 경우입니다. 결제위젯 연동 키(test_gck_)로 바꾸세요.

3서버에서 결제 승인하기

결제창에서 인증이 끝나면 토스가 브라우저를 /support/success?paymentKey=…&orderId=…&amount=…로 보냅니다. 이 시점에는 아직 돈이 움직이지 않았어요. 우리 서버가 확인하고 승인을 요청해야 결제가 완료됩니다.

먼저 토스 서버와 통신하는 함수를 만듭니다. 시크릿 키를 쓰므로 서버 전용 파일입니다.

📖 용어 풀이Basic 인증: "아이디:비밀번호"를 base64라는 방식으로 바꿔 요청 머리글(헤더)에 담아 보내는 인증 방법. 토스는 아이디 자리에 시크릿 키를, 비밀번호 자리는 비워 둡니다(그래서 키 뒤에 :를 붙임). base64는 암호화가 아니라 단순 변환이라, 이 요청은 반드시 서버에서만 보내야 합니다.

폴더 app/support/success를 만들고 page.js를 만듭니다. 흐름도의 ⑥~⑩이 순서대로 들어 있어요.

💡 코드에서 꼭 볼 세 곳
  1. 금액 비교: Number(amount) !== order.amount — 주소에 담긴 금액은 누구나 바꿀 수 있습니다. DB 기록과 다르면 승인하지 않아요.
  2. DB 금액으로 승인: confirmPayment({ …, amount: order.amount }) — 토스에도 우리 기록의 금액을 보냅니다. 실제 결제된 금액과 다르면 토스가 승인을 거절합니다(이중 안전장치).
  3. pending일 때만 변경: 이미 paid인 주문을 새로고침해도 다시 승인하거나 덮어쓰지 않습니다.
✅ 여기까지 됐는지 확인하는 법 — 첫 테스트 결제!
  1. 공개 페이지에서 금액을 고르고 이름·메시지를 쓴 뒤 "후원하기"
  2. 결제창에서 결제수단(기본 선택된 퀵계좌이체로 충분)을 진행합니다. 테스트 결제창에는 입력할 테스트용 값(휴대폰 번호, 비밀번호 등)이 화면에 안내되어 있어요. 안내대로 끝까지 진행하세요. 테스트 키라 돈은 나가지 않습니다.
  3. "☕ 후원해주셔서 고마워요!" 화면이 뜬다
  4. Neon → support 표: 방금 줄이 paid, payment_key와 paid_at이 채워져 있다
  5. 감사 화면에서 F5(새로고침) → 같은 감사 화면. 결제가 두 번 되지 않는다
🧪 금액 위조 막히는지 직접 해보기
  1. "후원하기" → 결제창에서 <로 닫기 (지금은 pending으로 남음)
  2. Neon → support 표에서 그 줄의 order_id를 복사
  3. 주소창에 http://localhost:3000/support/success?paymentKey=test&orderId=복사한값&amount=100 입력
  4. → "결제 금액이 올바르지 않아요", 그 줄은 failed / AMOUNT_MISMATCH. 터미널에는 [결제] 금액 불일치 … 요청=100 기록=3000 로그가 찍힌다
🆘 막혔을 때
"결제를 승인하지 못했어요" + 인증 관련 메시지

TOSS_SECRET_KEY가 클라이언트 키와 짝이 맞는지(둘 다 문서용, 또는 둘 다 내 결제위젯 연동 키) 확인하고 서버를 다시 켜세요.

감사 화면 대신 404가 떠요

폴더 경로가 정확히 app/support/success/page.js인지 확인하세요.

4결제 실패·취소 처리

결제가 끝까지 가지 못하는 경우는 두 갈래입니다.

경우토스의 반응우리가 할 일
결제 중 실패 (카드 한도 초과 등)브라우저를 failUrl로 보냄 (?code=…&message=…&orderId=…)실패 페이지에서 주문을 failed로 기록
구매자가 결제창을 닫음페이지 이동 없이 requestPayment가 에러를 냄 (USER_CANCEL)폼에서 에러를 받아 서버에 "취소됨"을 알림

폴더 app/support/fail을 만들고 page.js를 만듭니다.

서버 액션 파일 맨 아래에 cancelSupport를 추가합니다. (맨 위 import에 and도 추가)

후원 폼의 catch 부분에서 cancelSupport를 부릅니다. (import 한 줄과 catch 안의 두 줄이 바뀜)

✅ 여기까지 됐는지 확인하는 법
  1. "후원하기" → 결제창 <로 닫기 → "취소되었습니다." → Neon에서 그 줄이 failed / USER_CANCEL
  2. (실패 주소 흉내) pending 줄을 하나 만든 뒤(결제창을 띄운 상태에서 다른 탭으로 Neon을 봄) 그 order_id로 /support/fail?code=REJECT_CARD_COMPANY&message=카드사 거절&orderId=…에 접속 → "결제에 실패했어요 / 카드사 거절", 줄은 failed / REJECT_CARD_COMPANY
  3. /support/fail?code=PAY_PROCESS_CANCELED → "결제를 취소했어요 / 언제든 다시 후원할 수 있어요."
